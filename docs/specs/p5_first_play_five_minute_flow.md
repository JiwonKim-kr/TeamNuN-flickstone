## 배경

현재 공개 진입점은 5층 개발 런이다. 정식 콘텐츠인 탱탱볼·원시인·AI는 보상 후보에만 포함되어 첫 전투와 첫 5분 안에 등장한다고 보장할 수 없다. 반면 독립 전투에서는 숫자 키로 기물을 순환할 수 있지만 제출 심사자가 그 기능을 발견하기 어렵고, 이는 개발용 조작이지 첫 플레이 흐름이 아니다.

따라서 새 전투 규칙을 추가하지 않고 기존 결정론 전투와 정식 콘텐츠를 그대로 사용하는 제출용 직접 체험 경로를 제공한다. 심사자는 한 번의 선택으로 세 기물의 차이, 조준, 충돌, 피해 구역, 승패를 순서대로 확인할 수 있어야 한다.

## 목표

- 시작 후 30초 안에 첫 발사를 완료할 수 있다.
- 첫 전투에서 탱탱볼·원시인·AI를 모두 직접 조작할 수 있다.
- 5분 안에 각 기물의 차이와 피해 구역 규칙을 이해하고 전투 결과 또는 명확한 진행 변화를 본다.
- 전체 5층 런과 이어하기 기능은 그대로 유지한다.
- 데모 전용 UI가 core simulation, snapshot, save, content fingerprint를 바꾸지 않는다.

## 범위

- 시작 화면의 제출용 `5분 전투 체험` 진입 버튼
- 고정 seed와 고정 3기 편성을 사용하는 단일 전투
- 첫 진입 설명과 전투 중 짧은 상황별 도움말
- 전투 종료 후 재도전·전체 런 진입 선택
- 첫 플레이 흐름의 자동·수동 수용 검사
- 기존 Web 빌드 재배포와 브라우저 검수

## 비범위

- 새 기물, 적, 능력, 시너지, 상태 효과, 맵 또는 전투 공식
- 5기 편성이나 맵 수용량 변경
- 튜토리얼 전용으로 판정을 조작하는 scripted battle
- 강제 5분 타이머, 시간 초과 승패 또는 자동 조준
- 전체 런의 보상 풀·시작 로스터·저장 규칙 변경
- 신규 아트·효과음 제작

## 첫 5분 목표 흐름

| 경과 목표 | 플레이 경험 | 확인되는 요소 |
|---:|---|---|
| 0:00~0:15 | `5분 전투 체험` 선택, 한 장 설명 확인 | 게임 목표와 발사 조작 |
| 0:15~0:45 | 첫 기물 조준·발사 | 당기기, 힘, 예측 경로 |
| 0:45~2:00 | 탱탱볼과 원시인 행동 | 반사 차이, clean-launch 2배 |
| 2:00~3:30 | AI 행동과 피해 구역 상황 | 계산 HUD, 턴 시작 피해 |
| 3:30~5:00 | 체력 변화·처치·전투 종료 또는 우세 확인 | 공격 템포, 승패 목표, 재도전/전체 런 전환 |

5분 시점에 반드시 전투가 끝나야 하는 것은 아니다. 그러나 적어도 한 기물 처치 또는 어느 한 진영의 명확한 체력 우세가 보여야 한다. 고정 seed 수동 검수에서 이를 충족하지 못하면 이 명세를 조용히 벗어나 수치를 바꾸지 않고, 별도 밸런스 결정으로 올린다.

## 데이터·UI 계약

- `submission_showcase.json`은 UI 전용이며 runtime core catalog와 canonical fingerprint에 포함하지 않는다.
- 문서는 버전, map ref, encounter ref, 세 piece ref, seed만 허용하는 exact-key 구조다.
- 모든 ref는 numeric ID와 string ID가 현재 catalog에서 정확히 일치해야 한다.
- 전투 상태는 기존 `BattleSetupBuilder`/`RunBattleBridge`가 사용하는 동일 정의로 만든다. 별도 물리·피해·AI 경로를 만들지 않는다.
- 도움말 노출 여부는 해당 체험 세션의 UI 메모리만 사용한다. save와 snapshot에 기록하지 않는다.
- 일반 런과 독립 전투의 기존 키 조작·전투 판정은 바꾸지 않는다.
- 모바일/Web 포인터 조작을 기준으로 하며 키보드 `H`는 보조 수단이다.

## 오류 계약

- showcase JSON 파싱, exact key, ID pair, 편성 수, map/encounter 참조 중 하나라도 실패하면 체험 CTA를 비활성화하고 시작 화면에 진단 코드를 표시한다.
- 체험 구성 오류를 일반 런 구성으로 대체하지 않는다.
- 체험 전투 중 setup 실패는 결과 화면으로 위장하지 않고 오류 카드와 시작 화면 복귀를 제공한다.
- 체험 모드는 continue save를 읽거나 덮어쓰지 않는다.

## 수용 기준

1. 저장이 없는 첫 실행에서 제출용 CTA가 스크롤 없이 보이며 한 번의 선택으로 설명에 진입한다.
2. 설명을 닫은 뒤 30초 안에 포인터만으로 첫 발사가 가능하다.
3. 첫 전투 플레이어 편성이 탱탱볼·원시인·AI 순서로 정확히 구성된다.
4. 세 기물의 최초 행동 안내는 전투당 각각 한 번만 나타나며 조작을 막지 않는다.
5. 피해 구역 안내는 실제 해당 사건 이후 한 번만 나타난다.
6. AI 기본 궤적과 계산 정보, 원시인 2배, 탱탱볼 탄성은 기존 P5 계약과 동일하게 작동한다.
7. 체험 종료 뒤 재도전할 수 있고 전체 런 시작 화면으로 이동할 수 있다.
8. 체험 전후 기존 continue save bytes와 active run 상태가 바뀌지 않는다.
9. showcase 문서의 unknown key, ID mismatch, 누락, 중복 기물은 자동 검사에서 실패한다.
10. 고정 seed의 첫 5분 수동 검수에서 세 능력, 피해 구역, 체력 변화와 처치 또는 명확한 우세가 확인된다.
11. 영향 narrow, Godot import/smoke/manifest, 기존 P4-6 save/run 회귀가 통과한다.
12. Web 재빌드 후 공개 링크 direct entry, reload, Korean UI, pointer launch, 종료 CTA를 브라우저에서 확인한다.

## 사람 검수 체크리스트

- [ ] 첫 화면에서 무엇을 눌러야 하는지 즉시 알 수 있다.
- [ ] 설명을 한 번만 읽고 첫 발사가 가능하다.
- [ ] 탱탱볼·원시인·AI가 외형과 플레이 양쪽에서 구분된다.
- [ ] 안내 카드가 조준과 전투 화면을 과도하게 가리지 않는다.
- [ ] 피해 구역이 바닥 장식이 아니라 규칙으로 이해된다.
- [ ] 5분 안에 전투가 충분히 변화하며 다시 해보고 싶은 지점이 있다.

## 구현 기록

2026-08-26 core catalog·snapshot·save를 바꾸지 않고 UI 전용 strict showcase 설정, 첫 화면 기본 CTA, 시작 설명, 탱탱볼·원시인·AI 고정 편성 전투, 최초 행동·피해 구역 도움말, `H`/`?` 도움말 재열기, 종료 후 재도전·전체 런 복귀를 구현했다. 자동 narrow 16개는 exact key·중복 key·ID pair·중복 기물 오류와 실제 씬의 편성·저장 격리·도움말·종료 lifecycle을 통과했고, 기존 기물 표시 17개 및 import/smoke/manifest와 오케스트레이션 파이프라인도 통과했다. 첫 `verify --demo`의 5 FAIL 중 새 12종 목록에 맞지 않던 오케스트레이션 기대값은 수정·재통과했다. P5-FP 자체와 base gate는 통과했으며 기존 P2 terminal golden, P4 legacy snapshot, P5-DZ legacy snapshot 및 P4 production 600초 timeout 네 건은 통합 부채로 남는다. 고정 seed 5분 사람 검수와 Web 재배포·브라우저 검수도 남아 있다.
