P1의 명세 순서와 승인 경계를 관리한다. P1의 완료 목표는 개별 기물 능력 없이 공통 스탯만으로 두 팀의 전투를 끝까지 진행하고, 같은 시드와 양자화 입력에서 같은 결과를 재현하며, 배치 시뮬 결과를 기계 판독 가능한 형태로 내보내는 것이다.

- 4.5 피해 공식, 4.6 발사, 4.7 CTB, 4.8 턴 상태 머신, 4.9 승패
- 7.2 능력 트리거 목록, 7.7 기물 플래그 축
- 13장 UI·조작
- 14.1 결정론 원칙, 14.2 레이어 규칙, 14.4 리플레이
- 16장 검증·테스트 계획
- 17장 P1 완료 판정
- D-46~48과 22장 미결 사항 U-23, U-32, U-33

## 하위 명세 경계

### P1-1 · CTB / BattleState

포함:

- 전투 참여자와 진영·턴 참여·조작 가능·승패 포함 플래그의 P1 최소 상태
- CTB 다음 행동자 산출과 행동 후 CT 차감
- 런타임 추가·제거를 견디는 스케줄러 인터페이스
- `TURN_START → AIM → RESOLVE → TURN_END → CHECK` 상태 전이의 권위 상태
- 물리 시간과 독립된 추상 CT 시간

확정된 하위 결정:

- C-01~02: CT 임계값 10,000, 기본 속도 50~200·기본값 100
- C-03~05: 동률 우선순위, 런타임 참여자 장벽, 최대 32개 CTB 예보
- C-06~07: phase 전이, 정상 960틱과 강제 정산 240틱
- C-08~09: 독립 `BattleSnapshot` schema v1, 구현 API·진단·수용 규격

범위 밖: 마우스 입력, 발사 수치, 피해, 능력 효과, AI 샷 평가, 런 결과 처리.

### P1-2 · 발사 / 조준 / 궤적 예측

포함:

- 드래그 벡터를 고정 각도·정수 파워 명령으로 양자화하는 경계
- 취소와 최소 파워 미달 거부 시 CT·RNG·월드 불변 계약
- 무게 보정을 포함한 초기 속도 산출
- 권위 시뮬레이션과 같은 입력 명령을 사용하는 읽기 전용 궤적 예측
- Godot 입력·표시 어댑터와 엔진 독립 전투 명령의 분리

승인된 결정:

- L-01: `angle:uint16 + power_step:uint16`, schema v1 little-endian 6바이트
- L-02~03: 최대 드래그 192, 파워 256단계, 최소 32/256, 각도 256간격
- L-04~06: 기준 최대 속도 1,024, 절대상한 2,048, `sqrt(64 / mass)`, 공통 반올림·시계 방향 동률
- L-07~08: 최대 240틱, 첫 기물 충돌 또는 두 번째 벽 반사 종료, 4틱 표본·최대 64점
- L-09: 코어·UI 브리지·독립 기준값·Godot narrow 수용 규격

범위 밖: 기물별 각도 제한, 비행 중 추가 입력, 실제 아트, AI 후보 샷 탐색.

### P1-3 · 피해 해결

포함:

- P0 `BODY_COLLIDED` 이벤트에서 충돌 순간 접근 상대속도와 가해자·피해자를 확정하는 경계
- 공통 체력·공격력·크리티컬 확률의 P1 최소 전투 상태
- 비율 보정 → 아군 보정 → 고정 보정 → 최종 정수 피해 순서
- 속도 동률의 양방향 피해와 피해임계 미만의 무피해
- 같은 기물 쌍의 재충돌 피해 쿨다운
- 체력 0 파괴 요청을 P0의 공통 `BODY_DESTROYED` 경로로 정산

승인 완료:

- ✅ U-32 P1 기준 무게지수·질량비 범위·기준속도·피해임계속도
- ✅ U-33 P1 기준 크리티컬 배율과 적용 시점
- ✅ 아군 피해 감소 계수 0.5의 P1 기준값 채택
- ✅ 재충돌 피해 쿨다운 12틱
- ✅ half-away 최종 반올림과 임계 이상 최소 피해 1
- ✅ 기존 `BODY_COLLIDED` payload 의미 확장과 P0 golden hash 재고정
- ✅ 속력 동률 양방향 동시 피해와 같은 스텝 HP 0 기물의 후속 충돌 제외

상세 승인안과 회귀 범위는 `p1_damage_resolution.md` R-01~10에 정리되어 있다.

범위 밖: 개별 능력·시너지·상태이상 효과, 발사체, 부착물.

### P1-4 · 트리거 버스 / 전투 결과

포함:

- P1에서 발생 가능한 전투 사건을 정렬·큐잉하는 엔진 독립 트리거 버스
- `PASSIVE`, `ON_BATTLE_START`, `ON_TURN_START`, `ON_LAUNCH`, `ON_HIT_DEAL`, `ON_HIT_TAKE`, `ON_ALLY_COLLIDE`, `ON_WALL_BOUNCE`, `ON_MOVING`, `ON_DEATH_SELF`, `ON_KILL`, `ON_TURN_END`, `ON_BATTLE_END`의 등록·발생 경계
- 체력 0·고정 체력 소진·소멸 영역을 공통 파괴 사건으로 소비할 확장 지점
- 적·아군의 `counts_for_victory` 생존 수에 따른 승패 판정과 중립 제외
- 능력 효과가 없는 P1에서도 관찰 가능한 트리거 레코드

승인 대기:

- ⬜ 같은 시점 사건·트리거의 전체 우선순위
- ⬜ 트리거가 새 트리거를 만든 경우의 큐 규칙과 처리 한도
- ⬜ 연쇄 피해의 처치 귀속 규칙
- ⬜ 양 진영 동시 전멸 결과
- ⬜ U-23 실제 전투 RNG 소비 순서

범위 밖: 후보 트리거 `ON_ZONE_ENTER`·`ON_STOP`·`ON_ALLY_DEATH`, 효과 원자 실행, 콘텐츠 JSON 능력, D-12 전투 후 런 상태 처리.

### P1-5 · 회색상자 / 배치 시뮬 / 결정론 회귀

포함:

- 공통 스탯 기물만 사용하는 최소 플레이어 대 적 전투 씬
- manifest 등록 `PLACEHOLDER_` 자산만 사용하는 가독성 검증
- P3 AI가 아닌 P1 전용 결정론적 샷 공급 정책
- 다수 전투를 headless로 실행하고 전투별 결과·턴 수·시뮬 틱·피해·파괴 원인을 CSV로 출력하는 러너
- 동일 시드·입력 반복, 삽입 순서 교란, snapshot 복원 후 진행의 P1 결정론 회귀
- `pipeline/tests/run_*.py` 자동 발견과 `verify --full` 편입

승인 대기:

- ⬜ P1 전용 샷 공급 정책과 입력 fixture 형식
- ⬜ 배치 수, 전투 최대 턴, 교착 판정·종료 규칙
- ⬜ CSV 스키마와 필수 집계 지표
- **확정**: P1 전투 상태는 별도 `BattleSnapshot` schema로 분리하고 P0 `SimSnapshot` schema v1 정규 바이트를 길이와 함께 내장한다. P1 전투 필드 추가는 BattleSnapshot 버전만 올린다. (`p1_ctb_battle_state.md` C-08)
- ⬜ P1 회귀 골든의 갱신 승인 절차

범위 밖: P3 적 AI 품질, 콘텐츠별 승률 목표, 실제 아트·효과음, P6 최종 밸런스 판정.

## 공통 아키텍처 계약

- `src/core/sim/`은 원형 물리와 고정소수점의 엔진 독립 계층으로 유지한다.
- CTB, 피해, 트리거, 승패 같은 전투 규칙은 `src/core/battle/`에 둔다.
- Godot 입력·렌더·궤적선 표시는 `src/ui/` 또는 씬 어댑터에 두며 코어 상태를 직접 수정하지 않는다.
- 전투 계층은 `SimWorld`의 공개 API와 불변 `SimEvent`만 사용한다. P0 내부 구현에 결합하지 않는다.
- 새 상태가 결정 결과에 영향을 주면 정규 스냅샷·복제·회귀 범위를 함께 명세한다.
- 모든 반복, 동률 해소, 사건 처리, RNG 소비 순서를 안정 ID 기준으로 명시한다.
- release에서도 관찰 가능한 `SimStatus` 계열 오류 계약을 사용하며 `assert`에 실패 의미를 맡기지 않는다.
- enum 숫자는 append-only로 유지한다.

## 공통 승인 체크

- 설계 정본의 확정 항목과 모순이 없는가
- `⬜ 미정`을 임의로 확정하지 않았는가
- 공개 상태와 소유권이 `sim`·`battle`·UI 경계에 맞게 분리되는가
- 실패 전 상태 불변과 first-error-wins 계약이 있는가
- 스냅샷·복제·해시가 새 결정 상태를 빠짐없이 포함하는가
- 수용 기준이 headless 환경에서 관찰 가능한가
- 게임별 narrow runner가 `verify --full`에 자동 편입되는가
- P0·P1 플레이스홀더 정책을 지키는가
- art lock/gen/reskin과 SE gen/attach를 시작하지 않는가

## 필요 에셋

P1-5에서 회색상자 전투에 필요한 기물·전장·조준 표식만 추가한다. 모든 이미지는 `pipeline/scripts/placeholder_gen.py`로 생성하고 `PLACEHOLDER_` 접두사와 manifest 등록을 요구한다. 실제 아트·효과음은 전투 감각 승인 뒤로 미룬다.

## P1 전체 완료 판정

아래 조건을 모두 만족해야 P1 완료로 판정한다.

1. 다섯 하위 명세가 각각 승인·구현·검증되었다.
2. 개별 능력과 P3 AI 없이 공통 스탯만으로 플레이어 팀과 적 팀의 전투가 승패까지 진행된다.
3. 드래그 조준·취소·궤적선과 권위 발사가 같은 양자화 명령 계약을 사용한다.
4. 같은 시드·초기 상태·입력은 반복 실행과 지원 플랫폼에서 같은 전투 결과와 상태 해시를 낸다.
5. 배치 시뮬 러너가 CSV를 만들고 최초 결정론 불일치 또는 교착 전투를 재현 가능한 입력으로 보고한다.
6. narrow 테스트와 Godot이 활성화된 `pipeline/scripts/verify.py --full`이 통과한다.
7. 플레이스홀더 회색상자로 전투 감각을 사람이 검수한다.

## 승인 요청 범위

이 문서는 2026-08-20 사용자 승인으로 P1을 다섯 하위 명세로 분리하는 순서와 경계를 확정했다. 위 `⬜` 값과 세부 동작은 각 하위 명세에서 하나씩 제안·승인하며, 이 인덱스 승인만으로 확정되지 않는다.
