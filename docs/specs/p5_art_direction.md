## 목표

Flickstone의 서로 다른 기물 테마를 하나의 게임으로 보이게 하는 공통 시각 언어를 정하고, 첫 `art concept`에서 비교할 후보 범위와 런타임 규격을 확정한다. 컨셉 선택 뒤 5~15장의 대표 이미지를 준비해 별도 `art lock` 승인으로 넘긴다.

이번 문서는 스타일을 잠그거나 런타임 에셋을 교체하지 않는다. 승인 전에는 `pipeline/manifest.json`, 게임 씬, 런타임 코드를 바꾸지 않는다.

## 확정 정본과 현재 제약

- 탑다운 픽셀아트이며 물리 판정과 일치하도록 기물의 원형 실루엣을 유지한다.
- 기물은 세계관을 공유하지 않고 바둑돌·병뚜껑·원시인·AI·탱탱볼·체스·원소처럼 독립 테마를 가진다.
- 640×1,024 세로 Web 화면에서 이동·충돌·HP·현재 행동자·진영을 즉시 판독할 수 있어야 한다.
- 현재 placeholder는 기물 48×48을 4/3배로 표시해 실제 화면 지름 64px을 만든다. 이는 컨셉용 임시 계약이며 픽셀 그리드에는 불리하다.
- 매니페스트에는 48×48 아군/적 기물과 32×32 조준 표식 placeholder 3개만 있다. `style_guide`는 아직 `null`이다.
- 게임 기획상 세계관·스토리가 없으므로 lore를 새로 만들지 않고, 재질·문양·UI 규칙만 공통화한다.

## 권장 시각 방향

### A · 손에 잡히는 이세계 보드 토큰 — 권장

실제 재질감이 있는 원형 토큰을 어두운 전시용 게임판 위에 올린다. 바둑돌은 유광 도자기, 병뚜껑은 긁힌 금속, 탱탱볼은 반투명 고무처럼 재질이 즉시 읽힌다. 원시인·AI·체스·원소는 원형 베이스 위의 얼굴·문양·부조로 표현한다.

- 장점: 서로 다른 테마를 원형 토큰 규칙으로 묶고 현재 물리 판정과 가장 잘 맞는다.
- 비용: 재질별 하이라이트와 명암 방향을 일관되게 관리해야 한다.

### B · 네온 아케이드 칩

검은 배경, 강한 네온 테두리, 발광 문양 중심의 추상 토큰으로 표현한다.

- 장점: Web 화면과 썸네일에서 강한 대비, VFX 확장 용이.
- 비용: 병뚜껑·바둑돌 같은 물성 차이와 손맛이 약해질 수 있다.

### C · 고전 장난감 상자

밝은 나무·종이·금속 재질과 따뜻한 색을 사용해 수집형 보드게임 말처럼 표현한다.

- 장점: 친근하고 기물 수집·합성과 잘 맞는다.
- 비용: 전투의 위험감과 KILL 존의 긴장감이 약해질 수 있다.

## 선택에 따른 영향

### 64×64 이관 승인 시

- 현재 placeholder 48×48 사양과 `PIECE_SCALE = 4/3`을 64×64·1배 기준으로 이관해야 한다.
- 물리 크기·충돌 판정은 바뀌지 않고 렌더 경계와 매니페스트 사양만 바뀐다.
- P1/P2 씬, Web 첫 화면, manifest, import/smoke 회귀가 필요하다.

### 진영 오버레이 승인 시

- 개별 기물 PNG를 진영별로 두 벌 만들 필요가 없다.
- Sprite2D 아래/위에 공용 링이나 셰이더를 연결하는 UI 작업이 `art reskin` 전에 필요하다.
- 현재 행동자 노란 modulate와 진영 링이 충돌하지 않도록 active 표식은 화살표·펄스 등 별도 형태로 분리한다.

### 원형 토큰 규칙을 반려할 경우

- 캐릭터 전신·미니어처가 원 밖으로 돌출되면 시각 접촉과 실제 원 충돌의 차이를 허용할지 별도 승인해야 한다.
- 기물별 애니메이션·방향·회전 규칙이 추가되어 첫 양산 범위와 검수 비용이 크게 증가한다.

## 첫 컨셉 산출물 계약

- 저장 위치: `assets/art/concepts/`
- 후보마다 이미지와 프롬프트·시드·모델 메모를 함께 보존한다.
- 컨셉 이미지는 탐색용이며 매니페스트에 등록하거나 씬에 연결하지 않는다.
- 생성 뒤 크기·PNG·알파 여부를 `art_post.py probe`로 검사한다.
- 사람이 후보를 고른 뒤에만 `art lock` 학습 입력 5~15장을 확정한다.

## 환경 준비

저장소 아트 파이프라인은 Scenario 경유 생성 계약을 사용한다. 실제 생성 전 로컬 `.env`에 `SCENARIO_API_KEY`와 `SCENARIO_API_SECRET`이 필요하며 값은 문서·로그·커밋에 남기지 않는다. 키가 준비되지 않았으면 `scenario_client.py --dry-run`으로 요청·프롬프트만 검증한다.

## 승인 후 순서

1. P5-ART01~10 결정 반영
2. 세 방향의 스타일 보드 컨셉 생성·기계 검사
3. 사람의 방향 선택
4. 선택 방향 대표 이미지 6~9장 생성·기계 검사
5. 사람의 5~15장 선별
6. 별도 `art lock` 승인 및 스타일 가이드 작성
7. `art gen` → `art reskin` → import/smoke/Web 플레이 검수
