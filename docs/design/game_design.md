### 1.1 한 줄 정의

> 바둑알을 튕겨 상대를 파괴하거나 판 밖으로 밀어내는 알까기에, 기물 능력치 · CTB 턴제 · 지형 · 로그라이트 덱빌딩을 얹은 전술 게임.

### 1.2 원형(알까기)에서 달라지는 점

1. **장외는 특수 조건.** 기본 맵의 가장자리는 벽이며 기물은 반사된다. 장외는 지정된 스테이지에서만 열리며, 판 안쪽의 구덩이와 **같은 기믹**이다 (5장).
2. 기물에 **능력치**(체력·공격력·속도·무게)가 부여된다.
3. 장기판 외의 **다양한 맵**과 장애물·환경 요소가 존재한다.
4. 충돌 시 **속도가 빠른 쪽이 느린 쪽에게 피해**를 준다.
5. 기본 바둑알 외에 **특수 능력을 지닌 기물**이 등장한다.
6. 행동 순서는 속도 스탯 기반 **CTB** 방식이다.

   ↓
   ↑ 반복 (10층 보스 격파 시 다음 막)

### 4.2 기물의 물리 표현

- 모든 기물은 **원(circle)** 이다.
- 상태값은 `위치`, `속도` 두 개뿐이다.
- 회전은 시각 연출 전용이며 시뮬레이션에 영향을 주지 않는다.
- 기물 외에 **발사체**(총알·숨결 등)와 **부착물**(족쇄·손 등)이 별도 물리 객체로 존재한다. → 7.6-6

### 4.3 이동과 마찰

매 고정 스텝마다:

```
유효마찰 = 기본마찰 × 지형마찰배율 × 기물고유마찰
속도 = 속도 × (1 - 유효마찰 × DT)
속도 = 속도 + 지형가속도 × DT          # 컨베이어·조류·기물 능력에 의한 가속
위치 = 위치 + 속도 × DT
if |속도| < 정지임계: 속도 = 0
```

- 기본 시뮬레이션은 **120Hz**, `DT_NUM=1`, `DT_DEN=120`의 정확한 유리수다 (D-34).
- `SimWorld.step()`은 정확히 한 틱만 진행한다. 렌더 accumulator와 보간은 시뮬레이션 밖에서 처리한다.
- 모든 지속시간과 비행 중 입력 시점은 정수 틱으로 기록한다.
- P0 회색상자의 기본 마찰은 `5/2초⁻¹`이고 기본 기물·지형 마찰 배율은 1이다. 기본 상태의 틱당 감쇠율은 정확히 `47/48`이다 (D-35).
- 정지 임계는 `1/2 논리 단위/초`다. 제곱근 없이 속도 제곱을 `1/4`과 비교하며, 현재 틱의 외부 가속도가 0일 때만 속도를 0으로 만든다.
- 여러 존에 포함되면 `zone_id` 오름차순으로 정렬한다. 유효 마찰은 `기본마찰 × 기물고유배율 × 존1배율 × ...` 순서로 계산하고, 가속도는 같은 순서로 벡터 합산한다 (D-36).
- P0 존에는 우선순위와 override를 두지 않는다. 마찰 배율 0은 허용하지만 최종 `유효마찰 × DT`는 `0 이상 1 미만`이어야 하며, 가속도 합산도 승인된 안전 범위 안이어야 한다.
- 가속도 합이 정확히 0일 때만 D-35의 정지 임계 판정을 적용한다. 겹친 `KILL` 존은 P0-3의 소멸 정산에서 우선 처리한다.
- P0 외곽 경계는 화면 좌표 기준 시계 방향의 단순 볼록 폴리곤 3~64정점만 허용한다. 방향이 반대이거나 오목하면 자동 보정하지 않고 실패한다 (D-40).
- 외곽·내부 존 정점은 위치 안전 범위 ±8,192 안이어야 한다. 자기 교차, 중복 정점, 0길이 변, 연속 일직선 정점, 면적 0은 로드 실패다.
- 내부 마찰·가속·`KILL` 존은 자기 교차가 없는 단순 오목 폴리곤까지 허용한다. 오목한 외곽 전장은 P0 이후 내부 장애물 또는 검증된 볼록 분해 데이터로 확장한다.

마찰을 곱셈 감쇠로 두는 이유: 고정소수점에서 부호 뒤집힘이 발생하지 않고, "미끄러지다 멈춘다"는 알까기 감각과 일치한다.

> D-35의 값은 구현·회귀 검사용 초기값이다. 최종 감각과 밸런스는 플레이테스트 후 `balance.json`에서 조정한다.

### 4.4 충돌 해결

원-원 탄성 충돌. 스텝 내 처리 순서는 **기물 ID 오름차순으로 고정**한다 (결정론 보장).

```
n     = 정규화(위치B - 위치A)                  # 충돌 법선
v_rel = 내적(속도A - 속도B, n)                 # 접근 상대속도
if v_rel <= 0: 무시                            # 이미 멀어지는 중
j     = -(1 + 반발계수) × v_rel / (1/무게A + 1/무게B)
속도A += (j / 무게A) × n
속도B -= (j / 무게B) × n
겹침 보정: 겹친 깊이를 무게 역비로 분배해 즉시 분리
```

- **관통 방지**: 한 스텝의 이동량이 최소 반지름의 절반을 넘으면 그 스텝을 서브스텝으로 분할한다.
- **벽 충돌**: 무한 질량 대상의 반사. 피해 없음 (D-08).

**동적 서브스텝 (D-43)**

1. 기본 틱 시작 시 마찰과 외부 가속도를 `1/120초` 전체에 한 번 적용한다.
2. 갱신된 활성 기물 중 최대 속도와 최소 반지름으로 `N=max(1, ceil((최대속도/120)/(최소반지름/2)))`을 계산한다.
3. 모든 기물이 같은 월드 공통 `N`을 사용한다. 활성 기물이 없으면 N=1이다.
4. 위치 이동에는 정확한 유리수 `1/(120×N)`을 사용하고 마찰·외부 가속도를 서브스텝마다 다시 적용하지 않는다.
5. 이벤트 `substep`은 0~15 인덱스다. N의 최대는 16이다.
6. N이 16을 넘으면 이동 전에 `SIM_LIMIT_EXCEEDED`로 실패하며 속도나 N을 clamp하지 않는다.

반지름 8·속도 4,096의 승인된 최악 조합은 N=9이므로 P0 안전 범위 안에서 한도 여유가 있다.

**벽 모서리·다중 접촉 규칙 (D-41)**

- `edge_index`는 각 변의 시작 정점 인덱스다. 시계 방향 외곽 경계의 안쪽 법선은 변 벡터의 왼쪽 수직선이다.
- 동시에 관입한 벽 접촉을 모두 수집하고 `(관입 깊이 내림차순, edge_index 오름차순)`으로 처리한다.
- 가장 가까운 점이 변 내부면 해당 변의 안쪽 법선을 사용한다.
- 공유 꼭짓점이면 `꼭짓점→기물 중심`을 법선으로 사용한다. 두 점이 같으면 인접한 두 안쪽 법선의 합을 정규화한다.
- 공유 꼭짓점 접촉은 한 번만 만들고 낮은 인접 `edge_index`가 소유한다.
- 위치 관입 보정은 항상 수행하고, 속도 반사는 안쪽 법선 기준으로 벽을 향해 이동 중일 때만 수행한다.
- 보정 후 접촉을 다시 계산하며 64회 안에 관입이 해소되지 않으면 실패 처리한다.

**탄성 보정 규칙**

「탄성 N배」류의 능력은 반발계수를 곱하지 않는다. 반발계수가 1을 넘으면 충돌마다 에너지가 증가해 시뮬레이션이 발산하기 때문이다. 대신 **반사 시의 감속량을 1/N로 줄인다.**

```
유효반발계수 = 1 - (1 - 기본반발계수) / 탄성배수
```

예) 기본 반발계수 0.85, 탄성 2배 → `1 - 0.15/2 = 0.925`. 항상 1 미만이므로 발산하지 않는다.

**P0 회색상자 기본값 (D-42)**

- 기본 반발계수는 `17/20`이며 Q47.16 raw 값은 `55,706`이다. 원-원 충돌과 벽 반사에 같은 값을 쓴다.
- 반발계수 허용 범위는 `0 이상 1 미만`이며 1 이상은 데이터 실패다.
- 반지름 허용 범위는 8~128, 기본값은 32다.
- 무게 허용 범위는 1~256, 기본값은 64다.
- 시험 발사 속도는 저속 512, 기준 1,024, 최대 발사 2,048, 안전 한계 스트레스 4,096다.
- 탄성 강화는 위의 `1 - (1-e)/N` 공식만 사용한다.

### 4.5 피해 공식

사용자 정의 규칙: *충돌 시 현재 속도가 높은 기물이 낮은 기물에게 피해를 입힌다. 피해는 현재 속도, 공격력, 무게 차이를 반영한다.*

```
v_imp = |충돌 순간의 법선 방향 접근 상대속도|

if v_imp < 피해임계속도:                        # D-15
    피해 없음. 물리 반발만 적용
else:
    가해자 = |속도| 가 더 큰 기물   (동률이면 양쪽 모두)
    피해자 = 나머지

    무게비  = clamp( (가해자무게 / 피해자무게)^무게지수, 하한, 상한 )
    기본피해 = 가해자공격력 × (v_imp / 기준속도) × 무게비
```

**피해 연산 순서 (확정)**

> **비율 보정을 먼저 전부 적용한 뒤, 고정값을 더하고 뺀다.**

```
1) 기본피해   = 공격력 × (v_imp / 기준속도) × 무게비

2) 비율 보정  × (1 + 피해증가율 합)          # 파괴 시너지, 능력 배율 등
              × (1 − 피해감소율 합)          # 제어 시너지, 잎사귀 등

3) 아군 보정  × 0.5   (같은 진영끼리의 충돌일 때만, D-19)

4) 고정 보정  + 고정증가   (교활 시너지 +n×2 등)
              − 고정감소   (교활 −n×2, 강철 −n×2 등)

5) 최종       = max(1, round(결과))
```

- 고정값은 **최종 피해에 직접 더하고 뺀다.** 비율 보정의 영향을 받지 않는다.
- 따라서 `교활`·`강철`의 고정 보정은 **저피해 구간에서 상대적으로 강력**하고, `파괴`·`제어`의 비율 보정은 고피해 구간에서 강력하다. 두 축이 서로 다른 구간을 담당한다.
- ⬜ **크리티컬의 적용 시점 미정** — 2단계(비율)에 포함할지, 5단계 직전에 배율로 곱할지

**이 규칙의 중요한 귀결 — 튕겨 날린 적은 무기가 된다**

- 피해는 **일방향**이다. 빠른 쪽만 피해를 주고, 빠른 쪽은 그 충돌에서 피해를 받지 않는다.
- 따라서 넉백으로 날려보낸 적이 다른 적과 부딪히면, **날아간 적이 가해자가 되어 뒤쪽 적에게 피해를 준다.** 넉백은 소멸 영역이 없는 벽 맵에서도 피해 전달 수단으로 유효하다.
- 이때 사용되는 공격력은 **날아간 기물 본인의 공격력**이다. 밀어낸 쪽의 공격력은 반영되지 않는다.

**아군 충돌 (D-19)**

아군끼리의 충돌도 **동일한 공식으로 피해를 낸다.** 다만 결과에 감소 계수를 곱한다.

```
아군 피해 = 위 공식 × 아군피해감소계수     # 잠정 0.5 (러프값, balance.json에서 조정)
```

- 아군을 발판이나 당구알처럼 활용하는 플레이는 가능하되 **공짜가 아니다.**
- 「원시인」의 *벽이나 아군에게 충돌하지 않고* 조건이 실질적 리스크로 성립한다.
- **감소는 같은 진영끼리의 충돌에만 적용된다.** 중립 기물(7.7)은 어느 진영도 아니므로 누구에게든 **감소 없는 전액 피해**를 준다.

**설계 원칙**

- 방어력 스탯은 두지 않는다. 경감은 능력·유물의 곱연산 계수로만 표현한다.
- 동일 기물 쌍의 재충돌은 일정 시간 쿨다운 후에만 다시 피해를 낸다 (진동으로 인한 무한 피해 방지).

**크리티컬 (D-22)**

크리티컬은 전 기물이 공유하는 개념이며 **기본 확률은 0%** 다. 확률을 갖는 것은 능력이나 유물로 부여받은 기물뿐이다.

```
if RNG < 크리티컬확률:
    피해 = 피해 × 크리티컬배율      # 배율 ⬜ 미정
```

**⬜ 미정**: 무게지수, 무게비 상·하한, 기준속도, 피해임계속도, 재충돌 쿨다운, 크리티컬 배율.

### 4.6 발사

```
드래그벡터 = 기물 중심 - 마우스 위치            # 반대 방향으로 당김
파워       = clamp(|드래그벡터| / 최대드래그거리, 0, 1)
방향       = 정규화(드래그벡터)
무게보정   = (기준무게 / 자신의무게)^무게지수     # 무거울수록 느리게 나감
초기속도   = min(파워 × 최대발사속도 × 무게보정, 절대상한)
```

- **입력 양자화**: 각도와 파워를 정해진 단위로 스냅한 뒤 시뮬에 전달한다. 결정론과 리플레이의 전제 조건이다.
- 내부 각도는 한 바퀴 65,536단위다. `0`은 `+X`, 화면 기준 시계 방향으로 증가하며 45°=`8,192`, 90°=`16,384`다 (D-31).
- 조준 시간 제한 없음. 우클릭·ESC로 취소하며 취소 시 CT 변화 없음.
- 최소 파워 하한 미만은 발사 불가 (오조작 방지).
- 일부 기물은 **조준 각도가 제한**된다 (비숍·룩). 조준 UI가 각도 스냅을 지원해야 한다.
- 일부 기물은 **비행 중 추가 입력**을 받는다 (직각 자). 리플레이에 클릭 시점(스텝 번호)을 기록해야 한다.
- P0·P1 회색상자의 발사 절대상한은 **2,048 논리 단위/초**다. 플레이테스트 후 조정하더라도 물리 안전 상한 **4,096**을 넘지 않는다 (D-30).

**⬜ 미정**: 최대드래그거리, 최대발사속도(2,048 이하), 최소 파워 하한.

### 4.7 CTB (행동 순서)

```
각 기물: CT = 0
매 추상 틱마다 CT += 속도스탯
CT >= 임계값 인 기물이 행동, 행동 후 CT -= 임계값
```

- 실제로는 틱을 반복하지 않고 `(임계값 - CT) / 속도스탯` 의 최솟값으로 다음 행동자를 즉시 산출한다.
- 물리 해결에 걸리는 시간(초)은 CTB와 **무관**하다. CTB는 순수 추상 스케줄러다.
- 다음 N개 행동을 UI에 항상 노출한다.
- **런타임 중 기물이 추가·제거된다** (해골 소환, 닌자 분신, 좀비화, 부활). 스케줄러가 이를 지원해야 한다. → 7.6-5
- 런타임 생성 기물의 `body_id`는 생성 요청을 `(틱, 원인 기물 ID, 이벤트 타입 ID, 이벤트 내 순번)`으로 정렬한 뒤 단조 증가 카운터에서 할당한다 (D-37).

**라운드와 턴 (D-20)**

| 단위 | 정의 | 트리거 |
|---|---|---|
| **턴** | 한 기물의 차례. CTB가 결정한다 | `ON_TURN_START` / `ON_TURN_END` |
| **라운드** | **전투 한 판** | `ON_BATTLE_START` / `ON_BATTLE_END` |

- 라운드는 전투와 같은 말이다. 「라운드 시작 시」는 곧 전투 시작 시이며, 기물마다 다르지 않다.
- 「5라운드 동안 파괴되지 않으면」(용의 알) = **5번의 전투를 연속으로 버티면**. 런 스케일의 조건이다.
- 「한 라운드에 적을 셋 처치」(폰) = 한 전투 안에서 3처치.
- 라운드 조건은 속도 스탯의 영향을 받지 않는다.

**P1 확정 (D-46)**

- CT 임계값은 10,000, 기본 속도 저자 범위는 50~200, 기본값은 100이다.
- 준비 후보는 CT 초과분 내림차순 → 속도 내림차순 → 직전 행동 진영의 반대편 → body ID 오름차순으로 고른다.
- 현재 행동자는 별도 표시하고 이후 행동 10회를 같은 스케줄러 규칙으로 예보한다.
- 런타임에 추가되는 `has_turn=true` 참여자는 CT 0에서 시작하며 과거 추상 시간을 소급하지 않는다.
- 세부 정수식·장벽·오류 계약은 `docs/specs/p1_ctb_battle_state.md` C-01~05를 따른다.

### 4.8 턴 상태 머신

| 상태 | 내용 | 이탈 조건 |
|---|---|---|
| `BATTLE_START` | 전투 시작 규칙과 향후 전투 시작 트리거 처리 | 첫 행동자 선택 |
| `TURN_START` | 행동자 확정, 카메라 포커스, 턴 시작 트리거, 지속 효과 처리 | 처리 완료 |
| `AIM` | 플레이어 드래그 조준 / AI 샷 평가 | 발사 확정 |
| `RESOLVE` | 고정 스텝 물리 시뮬레이션. 충돌·피해·소멸·지형 처리 | 전 기물 정지, 또는 최대 시간 초과 후 강제 감속으로 정지 |
| `TURN_END` | 턴 종료 트리거, 파괴 정산 | 즉시 |
| `CHECK` | 승패 판정 | 계속 → `TURN_START` / 종료 → `BATTLE_END` |
| `BATTLE_END` | 종료된 전투의 terminal 상태 | 없음 |

**연쇄 충돌 규칙 (D-15)**

- 발사되지 않은 기물도 밀려나면서 정상적으로 피해를 주고받는다. 다단 연쇄가 성립한다.
- 단, 그 충돌의 `v_imp`가 피해임계속도 미만이면 피해는 0이고 물리 반발만 발생한다.
- **소멸 영역 진입에는 속도 임계값이 없다.** 아주 느리게 굴러 들어가도 즉사한다 (5장).

**P1 확정 (D-47)**: 정상 RESOLVE는 최대 960틱(8초)이다. 계속 움직이면 연속 가속 원천을 억제하고 매 틱 속도에 3/4를 곱하는 강제 정산을 최대 240틱(2초) 수행한다. 그래도 정지하지 않으면 hard stop으로 숨기지 않고 교착 오류로 중단한다. 세부 완료 조건과 원자성은 `docs/specs/p1_ctb_battle_state.md` C-06~07을 따른다.

### 4.9 승패

| 결과 | 조건 |
|---|---|
| 승리 | 적 진영 기물 전원 파괴 |
| 패배 | 아군 출전 기물 전원 파괴 |

중립 기물(7.7)은 승패 판정에 포함되지 않는다.

**⬜ 전투 종료 후 처리는 미정 (D-12)**

초안은 「아군 기물 전원 부활 + 체력 최대치 리셋」이었으나 재검토 중이다. 이 결정이 런의 소모 자원 구조 전체를 좌우한다 (9.6 참조).

**⬜ 미정**: 패배 시 런 처리(즉시 종료 여부), 장기 교착 방지 규칙.

## 5. 소멸 영역 (D-06 / D-07)

「장외」는 판 테두리 전용 규칙이 아니라, **소멸 영역**이라는 하나의 기믹이다. 테두리와 구덩이는 **같은 판정을 재사용하는 두 가지 배치 형태**다.

### 5.1 정의

> **소멸 영역에 진입한 기물은 즉시 파괴된다.** 체력·무적·소속과 무관하다.

| 항목 | 내용 |
|---|---|
| 판정 | 무조건 파괴. `destructible: false`(무적)인 기물도 예외 없음 |
| 속도 임계 | 없음. 아주 느리게 굴러 들어가도 파괴된다 |
| 진입 기준 | 기물 **중심점**. 반지름은 사용하지 않으며 경계선 위는 안전 (D-39) |
| 대상 | 아군·적·중립 전부 |
| 등장 | **특수 이벤트, 그리고 엘리트 전투 중 일부** (D-06) |
| 트리거 | **일반 파괴와 동일** (D-23). 소멸 전용 트리거 없음 |

- `SimBody`는 P0부터 `destructible: bool`을 보유하고 스냅샷·상태 해시에 포함한다. 기본값은 `true`다 (D-44).
- 소멸은 `destructible`을 확인하지 않는다. 이벤트 타입은 공통 `BODY_DESTROYED`이며 디버깅용 `cause_id`만 `KILL_BOUNDARY`·`KILL_ZONE`으로 구분한다.
- 관리 API `remove_body()`는 파괴가 아니므로 플래그를 확인하지 않고 `BODY_REMOVED`를 발생시킨다.

**파괴의 세 경로 (D-23)**

아래 셋은 전부 **같은 사건**이며 `ON_DEATH_SELF`·`ON_KILL`·`ON_ALLY_DEATH`를 동일하게 발동시킨다.

| 경로 | 예 |
|---|---|
| 체력 0 | 일반 피해 누적 |
| 고정 체력 소진 | 해골 (충돌 8회) |
| 소멸 영역 진입 | 장외, 구덩이 |

- 네크로맨서는 구덩이에 빠진 기물도 부활 대상으로 삼는다.
- 돼지저금통은 구덩이에 빠져도 「파괴 시」 효과가 발동해 골드를 돌려준다.
- 이 통합 덕분에 **소멸 영역 맵과 벽 맵에서 능력이 다르게 동작하는 문제가 사라진다.**

### 5.2 두 가지 배치 형태

| 형태 | 구현 | 예 |
|---|---|---|
| **테두리형 (장외)** | 맵 경계 폴리곤 **바깥 전체**를 소멸 영역으로 지정 | 판 밖으로 튕겨나가는 고전적 알까기 |
| **구덩이형** | 판 **안쪽**에 소멸 영역 폴리곤을 배치 | 판 중앙의 구멍, 갈라진 틈 |

- 두 형태는 **동일한 진입 판정 코드**를 쓴다. 데이터에서 영역의 위치만 다를 뿐이다.
- 한 맵에 둘을 함께 둘 수 있다. 테두리는 벽으로 막아두고 안쪽에만 구덩이를 파는 구성도 가능하다.
- 테두리형은 중심이 외곽 경계의 엄격한 내부에서 외부로 넘어갈 때, 구덩이형은 중심이 폴리곤의 엄격한 내부로 들어갈 때 소멸한다. 경계선 위는 안전하다 (D-39).
- 각 서브스텝에서 이전 중심→새 중심 선분을 검사하며, 여러 소멸 영역을 지나면 최초 교차를 채택한다. 초기 슬롯 중심이 소멸 영역 내부면 맵 로드 실패, 이후 순간이동으로 내부에 도착하면 즉시 소멸한다.

```json
// maps.json
"boundary_type": "WALL | KILL",        // 경계 바깥을 소멸 영역으로 할지
"zones": [
  { "type": "KILL", "shape": "polygon", "points": [[..]] }   // 구덩이
]
```

### 5.3 기본 맵의 경계 (D-08)

`boundary_type: WALL` 인 맵의 경계는 **순수 반사**다. 피해도 없고 소멸도 없다.

### 5.4 설계 함의

- 플레이어는 대부분의 전투를 「체력 깎기」로 치르다가, 엘리트·특수 이벤트에서 「밀어 넣기」라는 다른 규칙을 만난다. 이 대비가 소멸 영역 스테이지의 긴장감을 만든다.
- **넉백 자체는 소멸 영역이 없는 맵에서도 유효하다.** 피해는 「속도가 빠른 쪽이 느린 쪽에게」 주므로(4.5), 튕겨 날린 적은 그 자체가 발사체가 되어 뒤쪽 적에게 피해를 전달한다. 넉백은 소멸 전용 수단이 아니라 **피해 전달 및 진형 붕괴 수단**이다.
- 소멸을 일반 파괴로 통합했으므로(D-23), **벽 맵에서만 무력해지는 능력은 존재하지 않는다.** 능력은 어느 맵에서도 같은 방식으로 동작하고, 달라지는 것은 「죽이기가 얼마나 쉬운가」뿐이다.
- 구덩이형이 존재하므로 **판 안쪽에도 위험 지대를 둘 수 있다.** 테두리형보다 배치 자유도가 높고, 조준 난이도를 세밀하게 조절할 수 있다.

**⬜ 미정**

**엘리트 중 일부만 (확정)**

> **엘리트 전투가 전부 소멸 영역을 갖는 것은 아니다. 일부만이다.**

| 항목 | 내용 |
|---|---|
| 엘리트 배치 | 막당 2~3개 (9.1) |
| 그중 소멸 영역 | **일부** |
| 나머지 | 벽 맵. 순수 체력 승부 |

**이 결정이 만드는 것**

- 엘리트 노드가 **한 종류가 아니게 된다.** 「소멸 영역 엘리트」와 「벽 엘리트」는 같은 −2 라이프를 걸어도 요구하는 편성이 다르다.
- 넉백·밀어내기 계열 기물이 **어느 엘리트에 데려갈 것인가**라는 판단을 얻는다. 보유 10 / 출전 5 구조가 여기서 값을 한다.
- 소멸 영역은 여전히 희소하게 유지되므로 5.4의 「대비가 긴장감을 만든다」가 성립한다.

**⬜ 미정**

| 항목 |
|---|
| 진입 판정 기준 (기물 중심 / 완전 진입). **두 형태가 같은 기준을 써야 한다** |
| 소멸 영역 엘리트의 비율 (막당 2~3 중 몇 개인지) |
| 소멸 영역 엘리트가 더 나은 보상을 주는지 |
| 소멸 영역이 있는 스테이지임을 **사전 고지하는 방식** — 편성 선택의 전제이므로 노드 아이콘 단계에서 드러나야 한다 |

## 6. 스탯

| 스탯 | 역할 | 출처 |
|---|---|---|
| 체력 | 0이 되면 사망. 전투 단위로 리셋 | 사용자 정의 |
| 공격력 | 피해 공식의 계수 | 사용자 정의 |
| 속도 | **CTB 게이지 충전 속도 전용.** 피해와 무관 (D-13). 상승·하락이 어렵다 (D-21) | 사용자 정의 |
| 무게 | ① 발사 초기속도 ↓ ② 충돌 임펄스 저항 ↑ ③ 피해 무게비 ↑. 물리 안전 범위 1~256, P0 기본 64 (D-30/D-42) | 사용자 정의 |
| 반지름 | 피격 면적. 물리 시뮬에 필수. P0 범위 8~128, 기본 32 (D-42) | 시스템 요구 |
| 마찰 보정 | 기물 고유 감속률. 굴러가는 거리를 좌우 | 시스템 요구 |
| 크리티컬 확률 | 전 기물이 보유. **기본값 0%** (D-22) | 확정 |

- 반지름과 마찰 보정은 원-원 물리 시뮬을 성립시키기 위해 **반드시 필요한 값**이므로 스탯으로 편입한다. 플레이어에게 수치로 노출할지 여부는 미정.
- **파생 지표**(툴팁 노출 후보): `최대 발사속도`, `기준 피해`. 기물 간 서열을 한눈에 비교하기 위한 계산값이며 별도 스탯이 아니다.

**속도 스탯 설계 원칙 (D-21)**

속도는 쉽게 바뀌지 않는다. 따라서 **속도는 기물의 정체성에 가깝다.**

- 라운드는 전투 단위이므로(D-20) 라운드 조건을 쓰는 능력은 속도의 영향을 받지 않는다. 속도가 주는 이득은 **같은 전투 안에서 더 많이 행동한다**는 것뿐이며, 그만큼 순수하다.
- 반대로 속도를 올리거나 내리는 수단을 만들 때는 그만큼 큰 리스크나 비용을 붙인다. 감전의 「20% 둔화」처럼 일시적·제한적으로만 다룬다.

**⬜ 미정**: 각 스탯의 수치 범위와 기준값, 반지름·마찰의 UI 노출 여부, 크리티컬 배율.

| 태그 시너지 | 같은 태그를 2기 이상 배치하면 발동, 이후 선형 누적 (7.1.2) | 확정 (D-27) |
| **중복 보유** | **가능.** 합성(D-25)의 전제 조건 | 확정 (D-26) |
| **역할 분류** | **역할군 태그 5종**으로 확정 — `제어` `파괴` `교활` `기묘` `지원` (7.1.1) | 확정 |
| **레벨** | 합성으로 1~3. 테마 시너지 계수에 기여 (7.9) | 확정 (D-25) |
| 기물 총 개수 | **41종** (초기 해금 24종) | 확정 |
| 스탯 수치 | ⬜ 전부 미정 | |

#### 7.1.1 태그 (공식 용어)

> **태그**는 기물의 테마·역할군을 표기하는 분류 라벨이다. **같은 태그의 기물을 일정 수 배치하면 시너지 효과가 발동한다.**

| 항목 | 내용 |
|---|---|
| 축 | **테마 태그**와 **역할군 태그** 두 종류 |
| 역할군 | **반드시 1개 부여** (바둑돌만 예외) |
| 테마 | 해당되는 경우에만 부여. **없을 수 있다** |
| 보유 수 | **제한 없음.** 설계상 대개 1~2개지만 상한을 두지 않는다 |
| 플레이어 부여 | 이벤트·유물로 부여하는 태그는 **기물당 최대 1개** |
| 상속 | 도플갱어는 복사 대상의 태그를 모두 상속한다 (7.6.3.2) |
| 효과 | 같은 태그 기물을 **배치**한 수에 따라 시너지 발동 |

**역할군 태그 (5종 — 확정)**

| 태그 | 정의 |
|---|---|
| `제어` | 적 기물을 제한하거나 디버프를 거는 것이 주된 역할 |
| `파괴` | 강력한 피해 |
| `교활` | 특수 능력을 활용해 운용하는 기물 |
| `기묘` | 이질적인 능력 |
| `지원` | 아군 보조 |

**테마 태그 (7종 — 확정)**

| 태그 | 비고 |
|---|---|
| `원소` | 기존 |
| `언데드` | 기존 |
| `체스` | 기존 |
| `강철` | 신규. 금속·기계를 통합 |
| `무법자` | 신규. 야생·무법자를 통합 |
| `이상` | 신규 |
| `황금` | 신규 |
| `용` | 신규. 용의 알 · 드래곤 · 레서 드래곤 |

> 소속 기물 수가 적은 테마(도구·점착·장난감·용족 등)는 **부여하지 않는다.** 시너지가 발동하지 않는 태그는 존재 의미가 없다.

**시너지 계수 (확정)**

> **배치한 기물 1개마다 효과가 하나씩 쌓인다. 중복 기물도 각각 +1로 센다.**

| 규칙 | 내용 |
|---|---|
| **최소 발동 계수** | **2.** 같은 태그를 2개 이상 배치해야 시너지가 켜진다 |
| 누적 방식 | **선형.** 이후 1개 늘 때마다 추가 효과 |
| 중복 | 같은 기물을 둘 배치해도 **각각 +1** |

**이 규칙이 두 문제를 없앤다**

| 문제 | 해소 |
|---|---|
| 소속 기물이 적은 태그(`이상`·`황금` 2종)는 시너지를 못 켠다 | **중복 기물로 계수를 채우면 된다.** 종 수가 적어도 성립한다 |
| 합성 대기 중에는 중복 때문에 전투력이 떨어진다 | 중복도 세므로 **합성과 시너지가 서로를 방해하지 않는다** |

- 종(種) 수를 세는 조건과는 다르다. 무지개·킹의 해금 조건(「5종 동시 보유」)은 여전히 **서로 다른 5종**을 요구한다.

**시너지 — 효과는 7.1.2 참조**

| 남은 미정 |
|---|
| 시너지 효과 → **7.1.2에 확정** |
| 적 기물도 시너지를 갖는지 (`체스`는 양 진영 적용으로 확정, 나머지는 미정) |
| 태그를 부여하는 이벤트·유물의 형태 (기물당 1개 제한) |
| 퀸·킹·무지개는 이미 「전장의 [태그] 기물 수」를 참조한다. 시너지와 중복되는지 |

#### 7.1.2 시너지 효과

`n` = 그 태그의 시너지 계수 (배치된 기물 수, 최소 발동 2)

**역할군 시너지 (상한 모두 5)**

역할군 태그는 레벨의 영향을 받지 않으므로 계수 상한 5는 곧 **배치 5기 전원**을 뜻한다.

| 태그 | 효과 | 상한 |
|---|---|---|
| `제어` | 받는 피해 **(n×10)% 감소** | 5 |
| `파괴` | 주는 피해 **(n×10)% 증가** | 5 |
| `교활` | 충돌 시 받는 피해 **−n×2**, 주는 피해 **+n×2** (둘 다 고정값) | 5 |
| `기묘` | `기묘` 기물이 능력을 발동하면 **그 전투 동안 속도 +n**. **기물당 1회만** | 5 |
| `지원` | 아군 기물에 충돌할 때마다 `지원` 기물이 **받는 다음 피해 −n** | 5 |

**테마 시너지**

테마 태그는 **레벨만큼 계수가 오르므로**(7.9) 상한이 5보다 높을 수 있다.

| 태그 | 효과 | 상한 |
|---|---|---|
| `원소` | `원소` 기물의 **효과 수치 +n** ⬜ *밸런싱 필요* | ⬜ 미정 |
| `언데드` | 모든 `언데드` 기물의 **공격력 +n** | **없음** |
| `체스` | 계수에 따라 국면이 열린다 (아래) | 6 |
| `강철` | `강철` 기물이 받는 모든 피해 **−n×2**, 무게 **+n×5** | 8 |
| `무법자` | `무법자` 기물의 치명타 확률 **+n×5%**. 계수 6 이상이면 **치명타 피해 +50%** | 10 |
| `이상` | `이상` 기물이 파괴될 시 **전투 시작 위치에서 체력 1로 부활**. 계수 5 이상이면 **부활 2회** | 5 |
| `황금` | 획득 골드 **+n×5%** | **없음** |
| `용` | `용` 기물이 계수에 비례해 **스탯과 능력 피해 강화** ⬜ 수치 미정 | ⬜ 미정 |

**`체스` — 국면(Phase) 시너지**

계수에 따라 열리는 국면이 다르다. 모인 시너지만큼 활성화된다.

| 국면 | 필요 계수 | 조건 | 효과 |
|---|---|---|---|
| **오프닝** | **2** | 전투 시작 시 | 기물이 받는 **첫 피해 −50%** |
| **미들게임** | **4** | 기물 2개 파괴 시 (적·아군 구분 없음) | 다음 턴 기물의 **공격력 +50%** |
| **엔드게임** | **6** | 기물 4개 파괴 시 | 생존한 모든 기물이 **즉시 추가 턴** |

계수 2·4·6에서 순차적으로 열리며, 최소 발동 계수 2와 정합한다. 테마 태그는 레벨만큼 계수가 오르므로(7.9) 레벨 2 체스 기물 3기만으로도 엔드게임에 도달할 수 있다.

**`체스`는 진영을 가리지 않는다 (확정)**

> **국면의 효과는 판 위의 모든 `체스` 기물에 적용된다. 적·아군을 구분하지 않는다.**

| 항목 | 내용 |
|---|---|
| 효과 대상 | 판 위 **모든** `체스` 기물 (적 포함) |
| 발동 조건 | 「기물 2개·4개 파괴」도 적·아군 구분 없음 |
| 계수 산정 | **자신의 배치에 있는 `체스` 기물 수로만 발동한다.** 적의 체스 기물은 계수에 포함되지 않는다 |

**「체스는 체스가 카운터」**

상대도 `체스` 기물을 들고 있으면 내가 연 국면의 이득을 **상대도 그대로 가져간다.** 엔드게임의 추가 턴이 적 체스 기물에게도 주어지므로, 판을 뒤집는 마무리기가 될 수도 있고 반대로 역전을 허용할 수도 있다.

- 12종 시너지 중 **유일하게 진영을 가리지 않는 시너지**다. 나머지는 자기 진영 한정이다.
- 계수는 내 배치로만 세지만 **효과는 양쪽에 간다.** 내가 판을 열고 상대가 무임승차하는 구조다.
- 적 풀 27종에 `체스` 기물이 포함되므로(7.10) 이 상황은 실제로 발생한다.
- 체스 빌드를 굴릴 때는 **상대 구성에 체스가 있는지 확인하는 것**이 편성 판단이 된다. 특정 전투에서는 일부러 체스를 빼는 선택이 성립한다.
- 「체스판 위에서는 규칙이 모두에게 공평하다」는 컨셉과도 맞물린다.

### 7.2 능력 트리거 목록

사용자가 지정한 트리거: **턴 시작 · 턴 종료 · 충돌 시 · 적 처치 시 · 패시브(상시)**.

| 트리거 ID | 발동 시점 | 상태 | 요구한 기물 |
|---|---|---|---|
| `PASSIVE` | 상시 | 확정 | 병뚜껑, 탱탱볼, 퀸, 킹, AI |
| `ON_TURN_START` | 자신의 턴 시작 | 확정 | 네크로맨서, 슈뢰딩거 |

### 7.6 키워드

Slay the Spire식 키워드 체계. **규칙을 한 번 정의하고 능력 텍스트에서는 이름만 부른다.** 능력 텍스트가 짧아지고, 구현이 재사용되며, 새 기물이 기존 키워드를 조합하는 것만으로 만들어진다.

#### 7.6.2 부착 (확정 키워드)

**부착은 두 오브젝트 사이의 링크**다. 어느 쪽이 기물이고 어느 쪽이 부속물인지는 상관없다. 이 하나의 구조로 세 기물을 모두 표현한다.

| 기물 | 링크 구조 |
|---|---|
| 거머리 | 거머리 본체 ← 링크 → 충돌한 적. 부착 거리 0 (밀착) |
| 죄수 | 족쇄 ← 링크 → 죄수 본체의 **고정점**. 부착 거리 > 0 (끌려옴) |
| 끈끈이 | 손A ↔ 적1, 손B ↔ 적2, 손A ↔ 손B 의 링크 3개. 앵커 지점은 **충돌한 위치** |

**파라미터**

| 파라미터 | 값 | 설명 |
|---|---|---|
| **부착 강도** | **해제 불가** (확정) | 지속 턴이 끝나기 전에는 풀리지 않는다. 인장력·내구도 개념을 두지 않는다 |
| **부착 관성** | **기본값 낮게** (확정) | 낮을수록 채찍처럼 늦게 따라온다. 휘두르는 손맛을 우선한다 |
| **부착 거리** | 기물별 지정 | **중심 간 거리가 아니라 표면 간 거리**다. 0이면 정확히 맞닿는다 |
| **앵커 지점** | 표면 추종 / 고정점 / 충돌점 | 링크가 앵커의 어디에 연결되는가. 아래 표 참조 |
| **무게** | 양쪽의 무게 스탯 반영 (확정) | 아래 공식 참조 |

**앵커 지점**

링크는 「앵커 기물의 중심」이 아니라 **앵커 지점**에 연결된다. 기물마다 연결 방식이 다르다.

| 방식 | 앵커 지점 | 사용 |
|---|---|---|
| **표면 추종** (기본) | 앵커 위치 + 부착체 방향 × 앵커 반지름. 부착체가 어디에 있든 항상 그쪽 표면 | 거머리 |
| **고정점** | 앵커 위치 + 지정된 오프셋. 기물 데이터에 미리 정해 둔다 | 죄수 (족쇄 연결부) |
| **충돌점** | 충돌이 발생한 순간의 접점을 앵커의 로컬 좌표로 저장해 고정 | 끈끈이 (손이 붙은 자리) |

**구속 공식**

```
앵커지점 = 위 표에 따라 산출
목표거리 = 부착체반지름 + 부착거리          # 앵커지점 ↔ 부착체중심
오차     = 현재거리 - 목표거리

# 무게 역비로 분배 — 4.4의 겹침 보정과 동일한 원리
보정A = 오차 × (무게B / (무게A + 무게B)) × 부착관성
보정B = 오차 × (무게A / (무게A + 무게B)) × 부착관성

위치A += 방향  × 보정A
위치B += -방향 × 보정B

# 충돌 피해 계산에 쓰이는 속도는 위치 변화량에서 역산
속도 = (새 위치 - 이전 위치) / DT
```

- 앵커 지점을 「표면 추종」으로 두면 **부착 거리 0이 곧 표면 밀착**이 된다. 거머리가 여기에 해당한다.
- **가벼운 쪽이 더 많이 끌려간다.** 무거운 족쇄는 주인까지 흔들고, 가벼운 손은 적에게 거의 영향을 주지 않는다.
- 속도를 위치 변화량에서 역산하므로 **끌려오는 족쇄도 4.5의 「빠른 쪽이 가해자」 규칙을 그대로 타고 피해를 낸다.**
- 링크가 여럿일 때는 **링크 ID 오름차순으로 순차 해결**한다 (결정론 보장).

**충돌 판정 (확정)**

| 대상 | 처리 |
|---|---|
| 링크로 묶인 두 오브젝트끼리 | **충돌 응답 없음.** 임펄스·피해 모두 발생하지 않는다 |
| 위 두 오브젝트의 관통 | **막는다.** 목표거리 구속이 접촉 상태를 유지시키므로 서로를 통과하지 못한다 |
| 부착된 오브젝트 ↔ 제3의 기물·벽 | **정상 충돌.** 피해도 정상 발생 |

**앵커 소멸 (확정)**

> **앵커가 파괴되어도 부착된 쪽은 판에 남는다.**

| 기물 | 결과 |
|---|---|
| 죄수의 족쇄 | 링크가 끊긴 뒤에도 판에 남는다. 족쇄는 **처음부터 중립 기물**이다 (7.7) |
| 앵커가 소멸 영역에 빠진 경우 | 부착된 쪽은 함께 끌려가지 않는다. 링크만 끊긴다 |
| 거머리 | 숙주가 죽으면 그 자리에 남는다 (거머리 본체가 부착된 쪽) |
| 끈끈이의 손 | 붙어 있던 적이 죽어도 손은 남는다 |

**부착 취소 (능력 조건, 부착 강도와 무관)**

부착 강도는 「해제 불가」이지만, **능력의 성립 조건을 못 채우면 능력 자체가 불발되며 부착이 취소**된다.

- 끈끈이: 트리거 발동 시점에 **적 둘 모두에 부착되어 있지 않으면** 능력이 취소되고 손이 떨어진다.

**⬜ 미정**

| 항목 |
|---|
| 죄수의 고정점 위치, 부착 관성·부착 거리의 수치 범위 |
| 부착 지속 턴이 끝났을 때 부착된 쪽이 남는 속도를 갖는지 |

**고정점 방향 (확정)**

고정점 오프셋은 **월드 기준으로 고정**된다. 기물은 회전하지 않으므로(4.2) 죄수가 어느 방향으로 날아가도 족쇄는 늘 같은 쪽에 매달린다.

> 의도된 설계다. 족쇄가 붙은 방향 때문에 **편한 맵과 불편한 맵이 갈린다.** 이는 죄수라는 기물의 고정된 성격이며, 편성 단계에서 맵을 보고 판단할 재료가 된다.

#### 7.6.3 변신 (확정)

기물이 다른 기물로 바뀐다. **지속 범위만 기물별로 지정하고, 승계 규칙은 아래 하나로 통일한다.**

| 항목 | 규칙 |
|---|---|
| **체력** | **비율 유지.** 변신 전 `현재/최대` 비율을 새 기물의 최대 체력에 적용 |
| **CT** | **플레이어에게 유리한 방향으로 환산** (아래 참조) |
| **상태이상** | **전부 유지** |
| **부착 링크** | **전부 유지.** 붙어 있던 거머리·손·족쇄는 그대로 따라간다 |
| **누적 카운터** | **전부 유지** (좀비의 감염 횟수, 용의 알의 라운드 수 등) |
| **소속** | **변하지 않는다.** 좀비가 적을 좀비로 만들어도 그 기물은 적으로 남는다 |
| **위치·속도** | 그대로 승계 |
| **지속 범위** | 기물별 데이터 지정 |

| 기물 | 지속 범위 |
|---|---|
| 폰 | **영구** (런 지속). 원문의 「영구적으로 전환」 |
| 용의 알 → 드래곤 | **영구** (부화) |
| 좀비 | **1라운드(전투) 한정.** 전투가 끝나면 원래 기물로 돌아온다 |
| 도플갱어 | **1라운드(전투) 1회 발동, 파괴될 때까지 유지** (전투를 넘어 지속) |

**체력 비율 계산**

```
비율     = 현재체력 / 최대체력          # 고정소수점, 내림
새 체력  = max(1, floor(새 최대체력 × 비율))
```

- 도플갱어처럼 자주 변신하는 기물이 **회복 수단이 되지 않는다.**
- 체력 총량이 크게 다른 기물끼리 변신해도 체감이 일정하다.

**CT 환산**

CT 임계값은 전 기물 공통이므로, 변신으로 실제 바뀌는 것은 **속도 스탯에 따른 「다음 차례까지 남은 시간」**이다.

```
잔여        = CT_MAX - CT
남은시간_전 = 잔여 / 이전속도
남은시간_후 = 잔여 / 새속도

아군: 목표 = min(남은시간_전, 남은시간_후)     # 늦어지지 않는다
적  : 목표 = max(남은시간_전, 남은시간_후)     # 빨라지지 않는다

CT_new = CT_MAX - (목표 × 새속도)
```

- **아군은 변신으로 턴이 밀리지 않고, 속도가 빨라졌다면 그 이득은 그대로 챙긴다.**
- 적이 변신할 때는 반대로 적용해 플레이어가 손해 보지 않게 한다.
- 중립 기물은 턴이 없으므로(7.7) 해당 없음.

**반지름 변화**

새 기물의 반지름이 더 크면 주변과 겹칠 수 있다. 변신 직후 **4.4의 겹침 보정을 1회 적용**해 밀어낸다. 이때 밀려난 기물에게 피해는 발생하지 않는다.

**변신 대상 제한 (확정)**

기물 데이터에 `transformable: false` 플래그를 둔다. 이 기물은 **변신의 대상이 되지 않는다.**

| 제외 대상 | 사유 |
|---|---|
| 중립 기물 | 소속이 없어 감염 대상 자체가 성립하지 않는다 |
| 엘리트 | 전투의 핵심 위협을 우회로 무력화하는 것을 막는다 |
| 보스 | 위와 동일 |

#### 7.6.3.1 감염 (좀비 전용 규칙)

**카운트 조건 (확정)**

> **좀비가 가해자로서 피해를 입혔을 때만** 대상의 감염 수치가 오른다.

- 4.5의 가해자 판정(속도가 빠른 쪽)을 그대로 쓴다. 좀비가 느린 쪽이면 오르지 않는다.
- 피해임계속도 미만의 충돌은 피해가 없으므로(D-15) 감염도 없다.
- **좀비를 공격하는 것 자체는 안전하다.** 감염은 좀비 쪽의 능동적 투자다.

**세대별 감염 조건 (확정)**

세대가 올라갈수록 감염에 필요한 타격 횟수가 늘어난다. 연쇄는 살아있되 자연히 멈춘다.

| 세대 | 필요 타격 | 비고 |
|---|---|---|
| 1세대 (덱의 좀비) | 5회 | |
| 2세대 | 7회 | |
| 3세대 | 9회 | |
| n세대 | 3 + 2n | 증가폭·상한 ⬜ 미정 |

**구현 — 포인트 누적 방식**

세대가 다른 좀비들이 같은 대상을 때릴 때를 자연스럽게 처리하기 위해, 횟수가 아니라 **포인트**로 센다.

```
대상.감염포인트 += 10000 / 필요타격(가해좀비.세대)      # 정수 나눗셈
if 대상.감염포인트 >= 10000:
    대상을 좀비로 변신
    새 좀비.세대 = 가해좀비.세대 + 1
    새 좀비.감염포인트 = 0
```

- 1세대에게 3번, 2세대에게 2번 맞아도 합산되어 판정된다.
- UI에는 감염 진행도를 **퍼센트 또는 게이지**로 표시한다.

**설계 함의 — 연쇄는 양방향**

소속이 유지되므로 좀비로 변한 **적 기물도 「감염」 능력을 갖는다.** 그 적 좀비 입장에서 「적」은 플레이어 기물이므로, 이번엔 아군을 감염시키기 시작한다.

- 좀비화는 아군을 늘리는 수단이 아니라 **판 전체를 좀비판으로 바꾸는 판 흔들기**다.
- 다만 **전투 한정**이므로 아군이 감염되어도 런에는 흠집이 나지 않는다. 그 전투를 어떻게 넘기느냐의 문제로 국한된다.
- 세대별 조건 증가가 확산 속도에 제동을 건다.

#### 7.6.3.2 도플갱어 (전설 · 변신의 예외)

전설 등급에 맞춰 일반 변신 규칙에서 아래가 달라진다.

| 항목 | 일반 변신 | 도플갱어 |
|---|---|---|
| 발동 | 조건 충족 시마다 | **1라운드(전투)에 1회만** |
| 유지 | 기물별 지정 | **파괴될 때까지.** 전투를 넘어 유지된다 |
| 대상 제한 | 중립·엘리트·보스 불가 (`transformable: false`) | **엘리트·보스도 복사 가능** (전설 특권) |
| 체력 | 비율 유지 | **자신의 체력을 그대로 유지.** 대상의 체력은 가져오지 않는다 (아군을 복사할 때도 동일) |
| 그 외 능력치 | 대상의 값 | 대상의 값 (공격력·속도·무게·반지름·마찰·크리티컬 확률) |
| 능력 | 대상의 것 | **대상의 능력을 전부 가져온다** |
| **태그** | 대상의 것으로 교체 | **`이상` + `기묘` + 대상의 태그를 모두 상속.** 태그 수 제한 없음 |
| **레벨** | 대상의 레벨 | **항상 도플갱어 본인의 레벨(1).** 대상의 레벨은 따라오지 않는다 |

**규칙 정리**

- `transformable: false`는 **「변신의 대상이 되지 않는다」**에만 적용된다. **「복사의 원본이 되는 것」은 막지 않는다.** 도플갱어는 이 구분 덕에 보스를 복사할 수 있다.
- 체력만 제외하는 이유: 보스의 체력까지 베끼면 과도해진다. 도플갱어는 **「강한 적의 몸놀림과 재주를 흉내내되 맷집은 자기 것」**인 기물이다.
- 첫 충돌 대상이 곧 복사 대상이므로, **누구에게 먼저 부딪힐지 조준하는 것 자체가 이 기물의 플레이**다. 보스를 노리려면 그만큼 위험한 궤도를 그려야 한다.

**변신 유지와 리셋**

> 한 번 변신하면 **파괴되기 전까지** 그 모습을 유지한다. 전투가 끝나도 돌아오지 않는다.

| 사건 | 결과 |
|---|---|
| 첫 충돌 | 대상으로 변신 |
| 전투 종료 | **변신 유지** |
| 파괴 | 다음 전투 시작 시 **도플갱어 본체로 복귀** (⬜ D-12 확정 후 타이밍 재확인) |
| 복귀 후 | 다시 변신할 수 있다 |

- 좋은 대상을 복사하면 그 이득이 런 내내 이어진다. 반대로 **잘못 복사하면 파괴될 때까지 그대로**다.
- 「첫 충돌 대상이 곧 복사 대상」이라는 규칙의 무게가 크게 올라간다. 한 번의 조준이 여러 전투를 좌우한다.
- **파괴가 리셋 버튼**이 된다. 마음에 들지 않는 모습이라면 일부러 도플갱어를 잃는 선택이 성립한다. 라이프(D-24)를 걸지 않는 선에서 판단하는 문제가 된다.

**레벨은 훔치지 못한다**

도플갱어는 합성이 불가능하므로 **언제나 레벨 1**이다. 레벨 2 병뚜껑을 복사해도 **레벨 1 병뚜껑**이 된다.

- 레벨 고유 효과(7.9)는 가져오지 못한다. 능력과 능력치는 레벨 1 기준으로만 복사된다.
- 보스·엘리트가 고레벨이더라도 **레벨분의 강함은 훔칠 수 없다.** 도플갱어의 상한을 잡는 안전장치가 된다.
- 합성 재료로 쓸 때도 **레벨 1 기물과만** 짝이 맞는다.

**합성 (D-25) — 특수 판정**

| 규칙 | 내용 |
|---|---|
| 도플갱어끼리 합성 | **불가.** 레벨 2 도플갱어는 존재하지 않는다 |
| 변신 상태의 활용 | **복사한 기물의 합성 재료로 쓸 수 있다.** 병뚜껑으로 변신했다면 진짜 병뚜껑과 합쳐 레벨 2 병뚜껑을 만든다 |
| 결과 | 도플갱어는 **재료로 소모되어 사라진다** |

> 전설 하나를 일반 기물의 레벨업과 맞바꾸는 선택이다. 도플갱어를 계속 굴릴 것인가, 지금 필요한 기물을 강화할 것인가 — **전설을 소모품으로 쓰는 유일한 경로**다.

**표기 규칙**

| 위치 | 표기 |
|---|---|
| **도감** | 도플갱어의 **본 모습만** 표기한다. 변신 상태는 도감에 남지 않는다 |
| **덱 · 편성** | 이름 `도플갱어(병뚜껑)` / 스프라이트는 **변신한 기물의 것** / 카드 구석에 **도플갱어 아이콘** |

- 판 위에서는 변신한 모습으로 보이므로 적 AI와 플레이어 모두 그 기물로 인식한다.
- 덱에서는 아이콘 하나로 「이것은 사실 도플갱어다」가 즉시 구분된다.

**태그 상속의 파급**

도플갱어는 자신의 `이상`·`기묘`를 유지한 채 대상의 태그를 더한다. 병뚜껑(`강철`·`파괴`)을 복사하면 태그가 **4개**가 된다.

- 한 기물이 **여러 시너지에 동시에 기여**한다. 배치 5기 중 하나가 4개 태그를 채우는 셈이다.
- 무엇을 복사하느냐로 **그 전투의 시너지 구성을 바꿀 수 있다.** 전투 중에 빌드를 조정하는 유일한 수단이다.
- 전설다운 파괴력이 여기서 나온다. 스탯이 아니라 **시스템 접점의 수**가 강함의 근거다.

**⬜ 미정**

| 항목 |
|---|
| 복사한 능력이 「전투당 N회」 제한을 가진 경우, 그 횟수가 초기화되는지 |
| 보스의 판 전체 기믹을 복사했을 때 아군에게도 적용되는지 |


#### 7.6.3.3 용의 알 (전설 · 실패해도 결과가 남는 성장)

| 결과 | 조건 | 산물 |
|---|---|---|
| **성공** | 5라운드(전투) 연속으로 한 번도 파괴되지 않음 | **드래곤** |
| **실패** | 그 전에 파괴됨 | **레서 드래곤** — 채운 카운터에 비례한 성능 |

**확정 규칙**

| 항목 | 내용 |
|---|---|
| 카운터 저장 | **런에 저장.** 전투를 넘어 누적된다 |
| 실패 판정 | 파괴되면 카운터는 리셋되지 않고 **그 자리에서 확정**. 재도전 없음 |
| 레서 드래곤 형태 | **단일 기물 + 스탯 스케일.** 카운터에 비례한 계수를 기본 스탯에 곱한다 |
| 전환 시점 | **전투 종료 시.** 알이 깨진 전투는 알을 잃은 채로 치르고, 다음 전투부터 레서 드래곤으로 출전 |
| 부화 시점 | 동일하게 **전투 종료 시** (5라운드째 전투가 끝나면 드래곤) |

- 용의 알은 **완전 손실이 없는 기물**이다. 오래 지킬수록 좋은 것이 나오고, 일찍 깨져도 무언가는 남는다.
- 지킬수록 판에서 아무것도 못 하는 알을 데리고 다녀야 하므로, 「출전 슬롯 하나를 몇 전투 동안 비워둘 것인가」가 이 기물의 비용이다.
- 전환을 전투 종료 시로 통일했으므로 전투 중 기물이 갑자기 바뀌는 경우가 없다.

**⬜ 미정**

| 항목 |
|---|
| 카운터별 스탯 계수 |
| 알 상태의 스탯과 능력 (판 위에서 무엇을 하는가) |
| 드래곤·레서 드래곤이 덱에서 용의 알을 대체하는지, 추가되는지 |

#### 7.6.4 복사 (확정 키워드 · 규칙 미정)

| 정해야 할 것 | 관련 기물 |
|---|---|
| 최대 몇 개까지 (포식자는 3개 명시) | 포식자 |
| 같은 능력을 중복으로 얻으면 중첩되는가 | 포식자, 무지개 |
| 전투 종료 후에도 유지되는가 | 포식자 |
| 복사 대상이 「복사」 능력일 때의 처리 | 도플갱어 ↔ 포식자 |
| 무지개의 「내 [원소] 기물」이 덱 기준인지 출전 기물 기준인지 | 무지개 |

#### 7.6.5 보류 · 후보

| 구분 | 항목 | 사유 |
|---|---|---|
| **보류** | 소환체 (네크로맨서의 해골, 닌자의 분신) | 소환마다 규칙이 달라 공통 키워드로 묶기 어렵다. 개별 능력으로 기술 |
| 2순위 후보 | 가속 (수은·로켓) | 마찰을 이기는 가속. 상한과 해제 조건 필요 |
| 2순위 후보 | 충격파 (대지·드래곤·무지개) | 범위 피해 + 넉백 |
| 2순위 후보 | 성장 (돼지저금통·퀸) | 「비례해 강화」에서 **무엇이 오르는지**가 비어 있다 |
| 2순위 후보 | 조준 고정 (비숍·룩) | |
| 3순위 후보 | 관통 (나이트) | |
| 3순위 후보 | 발사체 (보안관·드래곤) | 기물이 아닌 물리 객체 |

> 태그는 키워드로 만들지 않는다. 기물 데이터의 태그 배열(기본 2개, 확장 가능)로 두고, 「전장의 [태그] 기물 수」를 세는 능력이 그 배열을 조회한다. 7.1.1 참조.

### 7.7 기물 플래그 축 · 중립 기물

죄수의 족쇄를 정의하다 보니, **판 위의 원형 물체 대부분이 「기물」 하나로 표현 가능**하다는 것이 드러났다. 종류를 늘리는 대신 **직교하는 플래그 축**을 둔다.

#### 7.7.1 플래그 축

| 축 | 값 | 의미 |
|---|---|---|
| `faction` | `player` / `enemy` / **`neutral`** | 소속. 아군 피해 감소(D-19)는 **같은 진영끼리만** 적용 |
| `has_turn` | true / false | CTB에 참여해 차례가 오는가. **`neutral`은 항상 false** (확정) |
| `controllable` | true / false | 차례가 왔을 때 플레이어·AI가 조준하는가 |
| `destructible` | true / false | 체력·고정 체력으로 파괴되는가 |
| `expire` | 조건 / 없음 | 소멸 조건 (턴 수, 충돌 횟수 등) |
| `transformable` | true / false | 변신의 대상이 될 수 있는가. **중립·엘리트·보스는 false** |
| `is_token` | true / false | **토큰 여부.** 아래 참조 |

**토큰 (확정)**

> **토큰**은 전투 중 능력으로 생성된 기물이다. **활성 시너지의 효과는 받지만, 시너지 계수에는 포함되지 않는다.**

| 항목 | 내용 |
|---|---|
| 예 | 네크로맨서가 부활시킨 해골, 닌자의 분신 |
| 시너지 효과 | **받는다** |
| 시너지 계수 | **포함되지 않는다** |

- 토큰을 대량 생산해 시너지 계수를 부풀리는 우회로를 막는다.
- 그러면서도 토큰이 아군 진영의 버프를 그대로 누리므로 소환 기물이 무의미해지지 않는다.
- ⬜ 닌자의 분신이 토큰인지 확인 필요. 좀비화된 적은 **변신**이지 생성이 아니므로 토큰이 아니다.
| `counts_for_victory` | true / false | 승패 판정에 포함되는가 |

이 축들의 조합으로 지금까지 나온 특수 물체가 전부 표현된다.

| 물체 | faction | has_turn | controllable | destructible | expire |
|---|---|---|---|---|---|
| 일반 아군 기물 | player | ✔ | ✔ | ✔ | — |
| 적 기물 | enemy | ✔ | ✔(AI) | ✔ | — |
| **죄수의 족쇄** | **neutral** | ✘ | ✘ | ✘ (무적) | — |
| 끈끈이의 손 | neutral | ✘ | ✘ | ✘ | 능력 종료 시 |
| 보안관의 총알 | player | ✘ | ✘ | ✘ | 첫 충돌 시 |
| 드래곤의 숨결 | player | ✘ | ✘ | ✘ | 사거리·시간 |
| 네크로맨서의 해골 | player | ✔ | ✔ | ✔ (고정 체력 8) | — |
| 닌자의 분신 | player | ✘ | ✘ | ✔ | 다음 턴 또는 충돌 5회 |

> 「발사체」와 「소환체」를 별도 개념으로 두지 않아도 된다. 둘 다 **플래그가 다른 기물**일 뿐이다. 시뮬레이터는 기물 하나만 알면 되고, 데이터가 나머지를 결정한다.

#### 7.7.2 중립 기물 (확정)

`faction: neutral` 인 기물.

| 항목 | 내용 |
|---|---|
| 피해 | **적·아군을 가리지 않고 피해를 준다.** 어느 진영도 아니므로 아군 감소(D-19)가 적용되지 않아 **항상 전액** |
| 공격력 | 자체 공격력을 갖는다 |
| 승패 | 판정에서 제외 |
| 턴 | **가질 수 없다.** 중립 기물은 CTB에 참여하지 않는다 (확정) |
| 조작 | 조작 불가 (`controllable: false`) |
| 파괴 | 개별 지정. 족쇄는 무적 |
| 소멸 영역 | **무적이어도 즉사** (5.1) |

**죄수의 실제 성격**

족쇄는 처음부터 중립이다. 따라서 **죄수는 자신의 족쇄로 아군을 전액 피해로 때린다.** 주인만은 링크 쌍이라 충돌 응답이 없어 안전하다(7.6.2). 고위험 기물로 성립한다.

#### 7.7.3 중립 기물 재사용 후보

| 후보 | 플래그 조합 | 비고 |
|---|---|---|
| **움직이는 맵 위험물** | neutral / 턴 없음 / 무적 | 현재 장애물은 전부 정적이다. 중립 기물을 쓰면 굴러다니는 바위·떠도는 추가 가능해진다 |
| **파괴 가능한 보물 상자** | neutral / 턴 없음 / 파괴 가능 | 부수면 골드. 골드가 이미 확정되어 있어(7.8-1) 바로 성립 |
| **적이 뿌리는 방해물** | neutral / 턴 없음 / 무적 또는 파괴 가능 | 적 능력의 결과물 |
| **쟁탈 목표물** | neutral / 턴 없음 / 무적 / 승패 포함 | 「특정 위치로 밀어 넣는 쪽이 이긴다」식 특수 전투 |

**⬜ 미정**

| 항목 |
|---|
| 「무적」이 상태이상·고정 체력에도 면역인가 (소멸 영역은 면역 아님이 확정) |
| AI 평가 함수에서 중립 기물을 어떻게 취급하는가 (위협으로 볼지, 무기로 쓸지) |
| 중립 기물이 판에 남은 채 전투가 끝나면 어떻게 되는가 |

### 7.8 런 스케일 카운터

일부 기물은 **전투를 넘어 누적되는 카운터**를 가진다.

| 기물 | 카운터 |
|---|---|
| 용의 알 | 무파괴로 버틴 전투 수 (0~5) |
| 폰 | 런 누적 처치 수 |

**시스템 요구사항**

- 카운터는 기물 종류가 아니라 **기물 인스턴스**에 붙는다. 같은 기물을 둘 보유하면 각각 별도로 센다.
- `RunState`에 인스턴스별 카운터를 저장해야 한다. 세이브·리플레이 대상이다.
- 전투 단위로 리셋되는 값(체력, 감염 포인트, 좀비 세대)과 **명확히 분리**해 관리한다.

| 구분 | 예 | 초기화 시점 |
|---|---|---|
| 전투 스코프 | 체력, 상태이상, 감염 포인트, 부착 링크, 도플갱어 발동 여부 | 전투 종료 |
| 런 스코프 | 용의 알 부화 카운터, 폰 누적 처치 수 | 런 종료 |

### 7.9 기물 레벨 (합성)

> **같은 레벨의 같은 기물 2개를 합치면 +1레벨 기물이 된다.** 레벨마다 능력치가 오르고 **레벨 고유 효과**가 붙는다.

D-09 초안의 「기물 개별 강화 없음」을 **D-25로 대체**한다. 다만 강화가 임의의 수치 상승이 아니라 **중복 획득을 자원으로 바꾸는 구조**이므로, 인플레가 아니라 선택이 된다.

| 항목 | 내용 |
|---|---|
| 재료 | 같은 기물 · 같은 레벨 2개 |
| 결과 | 해당 기물 +1레벨 1개 |
| 강화 내용 | 능력치 상승 + **레벨 고유 효과** |
| 합성 장소 | 휴식 노드 (10장) |
| 중복 보유 | 허용 (D-26) |

**비용 구조**

레벨 n을 만들려면 원본 기물이 2ⁿ⁻¹개 필요하다.

| 목표 레벨 | 필요한 원본 | 보유 상한 10 대비 |
|---|---|---|
| 2 | 2개 | 덱의 20% |
| **3 (상한)** | 4개 | **덱의 40%** |

**레벨 상한은 3 (확정).**

**레벨은 테마 시너지 계수를 올린다**

| 태그 종류 | 레벨의 영향 |
|---|---|
| **테마** | 레벨만큼 계수에 기여한다. 레벨 3 얼음은 `원소` 계수 **3** |
| **역할군** | 영향 없음. 항상 1 |

- 합성의 가치가 크게 오른다. **슬롯 하나로 테마 계수 3을 채울 수 있다.**
- 배치 5기가 전부 레벨 3이면 이론상 계수 15까지 도달하므로, `강철`(8)·`무법자`(10)의 높은 상한이 의미를 갖는다.
- 역할군은 레벨과 무관하므로 상한 5가 곧 배치 인원 수와 일치한다.

- **레벨 2가 현실적인 기준**, 레벨 3은 그 기물에 런을 걸겠다는 선언이 된다.
- 합성 전에는 같은 기물 2개가 보유 슬롯을 둘 차지하므로, **합성 대기 자체가 비용**이다.
- 같은 기물을 다시 얻는 경로는 **태그 가중치**로 해결한다 (10.2).

**해소되는 미정 — 폰의 「같은 레벨」**

폰의 승급 조건에 있던 「킹을 제외한 **같은 레벨**의 무작위 체스 기물로 전환」이 이 시스템으로 그대로 읽힌다. 레벨 2 폰은 레벨 2 체스 기물로 승급한다.

**⬜ 미정**

| 항목 |
|---|
| 레벨별 능력치 상승폭과 고유 효과의 설계 방침 |
| 합성이 휴식 노드에서만 가능한지 (상점·즉시 합성 여부) |
| 적 기물도 레벨을 사용하는지 (막별 난이도 스케일링에 재사용 가능) |
| 레벨이 붙은 기물의 도감·해금 표시 |
| 전설 기물도 합성 가능한지 |

### 7.10 적 기물 — 플레이어 기물의 재사용

**방침 (확정)**

> **전설 등급을 제외한 플레이어 기물을 조정해 적으로 재사용한다.** 적 전용 기물을 새로 설계하지 않는다.

| 목적 | 효과 |
|---|---|
| **학습** | 아직 써보지 못한 기물을 **적으로 먼저 만난다.** 능력을 몸으로 겪은 뒤 해금되므로 설명 없이 이해된다 |
| **해금 서사** | 「나를 괴롭히던 그 기물을 이제 내가 쓴다」는 경험 |
| **제작비** | 적 기물 16~20종을 새로 설계할 필요가 없다 |
| **일관성** | 같은 능력이 아군일 때와 적일 때 똑같이 동작한다. 규칙이 두 벌이 되지 않는다 |

**재사용 가능 풀**

| 구분 | 종 수 |
|---|---|
| 전체 아군 기물 | **41** |
| − 전설 9종 (무지개·킹·용의 알·드래곤·**레서 드래곤**·도플갱어·포식자·닌자·정복자) | 9 |
| − 번역 불가 (AI·직각 자·슈뢰딩거·돼지저금통·코인) | 5 |
| **= 적 풀** | **27종** |

9.5의 요구량(일반 적 16~20종)을 충분히 넘는다.

**조정 축**

적 버전이 원본과 달라지는 지점.

| 축 | 내용 |
|---|---|
| 스탯 | 막별 난이도에 맞춰 체력·공격력을 스케일 |
| AI 등급 | 각 기물에 `ai_grade` 부여 (D-17의 오차 등급) |
| AI 성향 | 공격형·밀어내기형·회피형 등 `ai_profile` 부여 |
| 능력 | 필요 시 일부 약화·변경. 원칙적으로는 그대로 |

**⬜ 번역되지 않는 기물 5종**

플레이어의 조작이나 골드를 전제한 능력은 적이 들었을 때 무의미하거나 앞뒤가 맞지 않는다.

| 기물 | 문제 |
|---|---|
| **AI** (계산) | 발사 각도·예상 경로 **표시**는 순수 UI 능력이다. 적 AI는 이미 최적 경로를 계산하므로 아무 의미가 없다 |
| **직각 자** (앵글샷) | 비행 중 클릭으로 90° 굴절. AI는 굴절 시점을 사전에 정해야 하므로 **탐색 차원이 하나 늘어난다** (각도 × 파워 × 굴절 시점). 12.3의 성능 예산을 크게 넘길 위험 |
| **슈뢰딩거** (양자 중첩) | 두 위치 중 하나를 선택. AI도 평가로 고를 수는 있으나 **탐색 비용이 2배**가 된다 |
| **돼지저금통** (저금) | 적이 들면 파괴 시 골드를 **플레이어가 얻게 되므로 오히려 보상**이 된다 |
| **코인** (황금) | 충돌 시 골드 획득. 적이 골드를 벌어봐야 쓸 곳이 없다 |

> **처리: 적 풀에서 제외 (확정).** 대체 능력을 만들지 않는다. 기물당 두 버전을 관리하는 비용을 피하고, 12.3의 AI 성능 예산도 지킨다. 이 5종은 「적으로 먼저 배운다」는 경험에서 빠지므로 **초기 해금 풀에 넣는 것이 자연스럽다.**

**엘리트 · 보스**

| 구분 | 방침 |
|---|---|
| 엘리트 6~9종 | **혼합 (확정).** 일부는 적 풀 27종의 **강화판**, 일부는 **엘리트 전용 신규 설계** |
| 보스 3종 | **별도 설계 (확정).** 보스는 판 전체를 흔드는 기믹을 갖기 때문에 기물 재사용과 성격이 다르다 |

**엘리트 전용 신규 기물의 승격**

> 별도 설계한 엘리트 기물이 **플레이어 기물로도 쓸 만하다면 플레이어 풀에 추가한다.**

이 방침은 기존 규칙에 그대로 얹힌다.

| 항목 | 결과 |
|---|---|
| 해금 경로 | **격파 해금** (7.10.1). 엘리트로 만나 이기면 해금 후보가 된다 |
| 서사 | 「강한 놈을 잡아서 그 힘을 얻는다」 |
| 도감 | 조우 → 해금 3단계가 그대로 적용된다 |
| 기물 총수 | 41종에서 신규 엘리트 수만큼 증가 |

- 엘리트 기물은 플레이어가 **가장 인상 깊게 겪는 적**이므로, 해금했을 때의 만족도가 일반 적보다 높다.
- 다만 엘리트용으로 설계된 스탯은 플레이어가 쓰기엔 과할 수 있다. **플레이어 버전은 하향한 값**을 별도로 둔다.

**⬜ 미정**

| 항목 |
|---|
| 강화판 / 신규 설계의 비율 |
| 「강화판」의 정의 — 스탯만 올릴지, 능력을 추가할지 |
| 신규 엘리트 기물의 플레이어 버전 하향 폭 |

> 보스를 별도로 두면서 **전설 8종은 순수 플레이어 전용**이 되었다. 적으로도 보스로도 나오지 않으므로 희소성이 유지된다.

### 7.10.1 해금 연동

> **적으로 만나 격파한 기물이 해금 후보에 오른다.** (D-11 해금형 메타와 연결)

「나를 괴롭히던 그 기물을 이제 내가 쓴다」가 규칙 자체가 된다. 해금 순서가 플레이어의 전투 이력에 따라 달라지므로 매 계정이 다른 경로를 밟는다.

**⬜ 구조적 문제 — 격파 해금이 닿지 않는 13종**

격파로 해금하려면 그 기물이 **적으로 등장해야** 한다. 그런데 전설 8종과 번역 불가 5종은 적으로 나오지 않는다.

| 구분 | 종 수 | 격파 해금 |
|---|---|---|
| 적 풀 | 27 | 가능 |
| 전설 | 8 | **불가** |
| 번역 불가 | 5 | **불가** |

**제안 — 초기 해금 24종 구성**

| 구성 | 종 수 |
|---|---|
| 전설 2종 (포식자 · 정복자) | 2 |
| 번역 불가 5종 (AI · 직각 자 · 슈뢰딩거 · 돼지저금통 · 코인) | 5 |
| 적 풀 27종 중 17종 | 17 |
| **초기 해금 계** | **24** |

| 미해금 | 종 수 | 해금 경로 |
|---|---|---|
| 적 풀 나머지 | 10 | **격파 해금** |
| 전설 (용의 알 · 닌자 · 도플갱어 · 무지개 · 킹 · 드래곤 · 레서 드래곤) | 7 | **개별 특별 조건** |
| **계** | **17** | (전체 41 − 초기 해금 24) |

- 전설 2종을 처음부터 쥐여주므로 **첫 런부터 「전설이 어떤 것인지」를 알 수 있다.** 이후의 전설 해금이 막연한 목표가 아니라 구체적인 기대가 된다.
- 격파 해금 대상이 10종이므로 초반 여러 런에 걸쳐 꾸준히 열린다.

**격파 기록 (확정)**

> **런에 실패해도 격파 기록은 남는다.**

- 격파 기록은 런이 아니라 **계정 단위 영구 데이터**다. `SaveManager`가 관리하며 `RunState`와 분리된다.
- 실패한 런도 성과를 남기므로, 초반 이탈 구간에서 「아무것도 못 얻고 끝났다」는 경험이 생기지 않는다.
- 3막 보스까지 못 가도 만난 적은 계속 늘어나므로 해금이 꾸준히 진행된다.

**전설의 해금 (확정 방향)**

> **전설 기물은 특별한 해금 조건을 달성해야 한다.** 격파 해금과 별개 경로다.

전설은 적으로도 보스로도 등장하지 않으므로 격파 해금이 닿지 않는다. 대신 조건 자체가 그 기물의 성격을 설명하는 편이 좋다.

**⬜ 짚어야 할 점 — 드래곤은 독립 해금 대상인가**

드래곤은 「용의 알의 부화 결과」로만 얻는다(7.6.3.3). 그렇다면 드래곤은 해금 대상이 아니라 **용의 알에 딸린 결과물**이며, 전설 해금 대상은 7종이 된다.

| 전설 | 해금 대상 여부 |
|---|---|
| 용의 알 | ○ |
| 드래곤 | ✕ — 용의 알의 부화 결과 |
| 무지개 · 킹 · 도플갱어 · 포식자 · 닌자 · 정복자 | ○ |

**전설 해금 조건 표**

| 기물 | 조건 | 경로 유형 |
|---|---|---|
| **포식자** | 없음 — **초기 해금** | 초기 |
| **정복자** | 없음 — **초기 해금** | 초기 |
| **용의 알** | 「용의 알을 얻는 이벤트」를 만나 획득 | 이벤트 |
| **닌자** | **닌자를 상대로 싸우는 이벤트 전투**를 치른 뒤 | 이벤트 |
| **도플갱어** | 기물 선택지에 섞여 나오는 **위장 개체**를 획득 (7.10.2) | 관찰 |
| **무지개** | 한 런에서 **`원소` 태그 기물 5종 동시 보유** | 태그 완성 |
| **킹** | 한 런에서 **`체스` 태그 기물 5종 동시 보유** | 태그 완성 |
| **드래곤** | **용의 알을 부화시킬 것.** 획득 전까지 도감에서도 미공개 | 부화 |
| **레서 드래곤** | **용의 알을 부화 전에 잃을 것.** 실패 경로 | 부화 |

**경로가 다섯 갈래로 갈린다**

| 유형 | 해당 | 성격 |
|---|---|---|
| 초기 | 포식자 · 정복자 | 처음부터 전설을 쥐고 시작해 「전설이 어떤 것인지」를 먼저 배운다 |
| 이벤트 | 용의 알 · 닌자 | 특정 이벤트를 만나야 한다. 운과 탐색 |
| 관찰 | 도플갱어 | 선택지를 유심히 보는 플레이 |
| 태그 완성 | 무지개 · 킹 | 덱 대부분을 한 태그로 채우는 빌드를 완성해야 한다 |
| 부화 | 드래곤 · 레서 드래곤 | 용의 알을 지켜내면 드래곤, 잃으면 레서 드래곤. **어느 쪽이든 해금이 진행된다** |

> 무지개·킹은 **능력 자체가 조건을 말하고 있다.** 보유 상한이 7~8이므로 한 태그 5종을 모으는 것은 덱 대부분을 그 태그로 채우는 선택이 된다. 조건 달성이 곧 하나의 빌드가 되고, 그 빌드를 완성한 사람이 그 태그의 정점을 받는다.

**전설도 이벤트 전투에서는 적으로 등장한다**

닌자 해금 조건에 따라, **전설이 일반 적 풀에는 없지만 지정된 이벤트 전투에는 적으로 나올 수 있다**는 예외가 생긴다. 「적으로 만나 배운 뒤 손에 넣는다」는 원칙이 전설에도 일부 적용되는 셈이다.

**해금 전용 이벤트**

이벤트 15~20종(9.5) 중 최소 2개가 해금 전용이다.

| 이벤트 | 역할 |
|---|---|
| 용의 알 이벤트 | 용의 알을 획득 → 해금 |
| 닌자 이벤트 | 닌자를 상대로 전투 → 해금 |

### 7.10.2 도감과 정보 은닉

**확정 사항**

| 항목 | 내용 |
|---|---|
| 도감 | 기물 목록을 보는 화면이 존재한다 |
| 드래곤 | **획득 전까지 도감에서도 미공개** |
| 용의 알 툴팁 | 드래곤 해금 전까지 **드래곤을 명시적으로 언급하지 않는다** |

능력 텍스트가 해금 상태에 따라 달라진다는 뜻이다. 데이터에 **조건부 텍스트**가 필요하다.

```json
"abilities": [{
  "id": "hatch",
  "text":          "5라운드 동안 한 번도 파괴되지 않으면 부화한다.",
  "text_revealed": "5라운드 동안 한 번도 파괴되지 않으면 드래곤으로 부화한다.",
  "reveal_key":    "dragon"
}]
```

**제안 — 도감의 3단계 공개**

격파 해금(7.10.1)이 「적으로 만난 기물」을 추적하므로, 도감도 같은 축으로 3단계를 두면 규칙이 하나로 통일된다.

| 단계 | 조건 | 표시 |
|---|---|---|
| **미공개** | 만난 적도 없다 | 실루엣, 이름 `???` |
| **조우** | 적으로 만났다 | 이름·외형·스탯 공개. 능력은 **발동을 목격한 것만** (7.10.2.1) |
| **해금** | 손에 넣었다 | 능력 포함 전체 공개, 사용 가능 |

**능력을 조우 단계에서 감추는 이유**

겪은 것과 아는 것을 구분한다. 도감이 정답지가 되지 않고, **손에 넣는 순간에도 발견의 여지가 남는다.** 적으로 만났을 때 무엇을 했는지는 플레이어의 기억에 남기고, 문서로 정리해주지 않는다.

- 드래곤·레서 드래곤·도플갱어처럼 적으로 등장하지 않는 기물은 **해금 전까지 미공개 단계에 머문다.** 별도 규칙 없이 처리된다.
- 「도감을 채운다」가 격파 해금의 시각적 진행도 역할을 겸한다.

### 7.10.2.1 능력 공개 — 발동한 것만 (확정)

> **한 번이라도 눈앞에서 터진 능력만 공개된다.** 능력 단위로 열리며, 한 번 열리면 계속 보인다.

| 항목 | 내용 |
|---|---|
| 공개 단위 | **능력 하나씩.** 기물 단위가 아니다 |
| 공개 조건 | 그 능력이 실제로 발동하는 것을 목격 |
| 공개 범위 | **계정 영구.** 런이 끝나도 유지된다 (격파 기록과 같은 저장소) |
| 표시 위치 | 전투 중 적 기물 툴팁 · 도감 |
| 미공개 능력 | 슬롯은 보이되 내용은 `???`. **「아직 못 본 능력이 하나 더 있다」는 것은 알 수 있다** |

**패시브의 취급**

패시브는 상시 적용이라 「발동 시점」이 모호하다. **그 효과가 실제로 결과를 바꾼 순간**을 발동으로 본다.

| 예 | 공개 시점 |
|---|---|
| 강철구 「받는 피해 −25%」 | 실제로 피해가 경감된 첫 충돌 |
| 유리알 「벽 반사 시 속도 감소 없음」 | 벽에 처음 반사되었을 때 |

**설계 의도**

- 첫 조우는 여전히 미지수지만, **한 번 당하면 다음부터는 대응할 수 있다.** 학습이 누적된다.
- 미공개 슬롯이 보이므로 「이 기물은 아직 뭔가 더 숨기고 있다」는 긴장이 유지된다.
- 도감을 채우는 행위가 기물 수집이 아니라 **지식 수집**이 된다.

**⬜ 미정**

| 항목 |
|---|
| 조우 단계에서 해금 조건을 알려주는지 |
| 레서 드래곤의 능력 |
| 다른 기물에도 조건부 텍스트가 필요한 곳이 있는지 |

### 7.10.3 도플갱어의 위장 해금

> **미해금 상태의 도플갱어는 기물 선택지에 「미묘하게 다른 기물」로 위장해 나타난다.** 그것을 고르면 도플갱어를 얻고 해금된다. 이후로는 본체 이름으로 등장한다.

사실상 처음부터 풀에 있으나 **정체를 가려둔 형태**다. 도플갱어라는 기물의 성격이 해금 방식 자체에 반영된다.

| 항목 | 내용 |
|---|---|
| 등장 | 기물 보상·상점의 선택지 중 한 칸이 낮은 확률로 위장 개체가 된다 |
| 위장 형태 | 기존 기물처럼 보이되 **미묘하게 다르다** |
| 획득 | 고르면 **즉시** 정체가 밝혀지고 도플갱어를 얻으며 해금 |
| 해금 이후 | 위장 등장이 사라지고 정상적으로 도플갱어로 나온다 |
| 난수 | 등장 확률은 런 시드에 묶인 결정론 RNG (D-18) |

**설계 의도**

- 공략을 찾아본 플레이어와 그렇지 않은 플레이어 모두에게 각각의 재미가 있다. 모르면 우연한 발견이고, 알면 **선택지를 유심히 보는 플레이**가 생긴다.
- 해금이 「반복 횟수」가 아니라 **관찰**로 열린다. 다른 전설과 결이 다른 경로 하나가 확보된다.

**위장 단서 (확정)**

세 가지를 함께 쓴다. 하나만으로는 놓치기 쉽고, 셋이 겹치면 「뭔가 이상하다」는 감각이 생긴다.

| 단서 | 예 |
|---|---|
| **스탯이 미세하게 다름** | 체력이 1 높거나 무게가 살짝 다르다 |
| **설명문이 미묘히 다름** | 어미나 단어 하나가 미끄러진다 |
| **이름의 글자 하나** | 비슷한 글자로 바뀌어 있다 |

- 정체가 **획득 즉시** 밝혀지므로, 단서를 못 봐도 고르기만 하면 해금된다. 단서는 「미리 알아채는 재미」를 위한 것이지 관문이 아니다.
- 위장 개체의 스탯은 **순수한 미끼**다. 획득하면 도플갱어의 스탯으로 대체된다.
- 고르지 않고 지나가도 손해는 없다. 다음 기회에 다시 나온다.

**데이터 구조**

```json
// doppelganger_disguises.json
{
  "base_piece": "steel_ball",
  "fake_name": "",
  "fake_description": "",
  "stat_delta": { "hp": 1, "wgt": -1 }
}
```

**⬜ 미정**

| 항목 |
|---|
| 위장 대상이 되는 기물의 선정 규칙 (무작위 / 지정 목록) |
| 위장 개체의 등장 확률 |
| 위장 개체가 같은 선택지 화면에 원본과 함께 나올 수 있는지 |

**⬜ 남은 미정**

| 항목 |
|---|

## 9. 런 구조

### 9.1 확정 사항

| 항목 | 값 |
|---|---|
| 형태 | StS식 분기 노드맵 (D-05) |
| 막(Act) 수 | **3** |
| 막당 층(노드) 수 | **10** |
| 층 구성 | 마지막 10층은 **보스** 고정 |
| 엘리트 배치 | 막당 **2~3개** 배치. 분기 선택으로 **회피 가능**. 그중 **일부만 소멸 영역** (5장) |
| **막당 전투 수** | **6~7회** (보스 1 포함) |
| 노드 유형 | 일반 전투 / 엘리트 전투 / 상점 / 이벤트 / 휴식 / 보스 |
| 런 전체 | **30층 / 전투 18~21회 / 비전투 9~12회** |

> **용어 주의**: 여기서 말하는 「라운드」는 **노드(층)**를 가리킨다. D-20의 「라운드 = 전투 한 판」과 다른 단위이므로, 이 문서는 런 구조에서 **「층」 또는 「노드」**로 표기한다. 상점·이벤트·휴식은 전투가 아니므로 기물 능력의 라운드 카운터(용의 알 등)를 올리지 않는다.

### 9.2 덱 규칙

| 항목 | 값 |
|---|---|
| 기물 보유 상한 | **최초 10.** 이벤트·유물·상점으로 상향 가능 |
| 출전 상한 | **최초 5.** 이벤트·유물·상점으로 상향 가능 |
| 배치 | 맵이 지정한 고정 슬롯에 순서만 선택 (D-14) |
| 실제 출전 인원 | `min(출전 상한, 보유 수, 맵의 슬롯 수)` |

- **보유 10 / 출전 5로 시작하므로 런 첫 전투부터 편성 선택이 있다.** 매 전투 전에 맵과 적 구성을 보고 누구를 내보낼지 고른다.
- 두 상한이 각각 오르므로 **성장 방향에 선택지가 생긴다** — 폭(보유)을 넓힐 것인가, 화력(출전)을 늘릴 것인가.
- 보유 상한을 올리는 것은 전투력을 직접 올리지 않는다. **상황 대응력**을 사는 것이다.
- 맵의 슬롯 수가 출전 상한보다 적으면 맵이 제한한다. 좁은 맵은 그 자체로 편성 압박이 된다.

**⬜ 미정**

| 항목 |
|---|
| 층별 노드 유형 출현 확률 |
| 분기 폭 (한 층에 노드 몇 개를 제시할지) |
| 시작 덱 구성 |
| 기물 방출 수단 |
| 보유·출전 상한의 최대치 |
| 전투 패배 시 런 처리 |

### 9.4 시간 예산 (잠정)

```
약 60분(3600초) 배분

  비전투 노드  10.5회 × 40초 =  420초
  전투 후 보상 19.5회 × 20초 =  390초
  ────────────────────────────────────
  전투에 쓸 수 있는 시간      = 2790초
  전투 1회당                 ≈ 143초 ≈ 2.4분
```

전투 1회 2.4분은 **턴당 8초 기준으로 약 18턴**이다. 아군 5 + 적 4면 각 기물이 2턴씩 쓰는 분량이다.

> **이 항목은 플레이테스트 이후에 조정한다.** 페이싱은 종이 위에서 확정할 수 없다. P1의 배치 시뮬 러너로 실제 턴 수 분포를 측정한 뒤 판단한다.

| 조정 후보 | 효과 | 대가 |
|---|---|---|
| 물리 해결 배속 2× 기본 | 전투당 30~40초 절감. **결정론 물리라 결과에 영향 없음** | 타격감 희생 |
| 막당 층 수 하향 (10 → 8) | 런 45분 수준 | 볼륨 감소 |
| 적 수 축소 (4 → 2~3) | 턴 수가 직접 감소 | 연쇄 충돌의 맛이 준다 |
| 피해량 상향 (2~3방 컷) | 유효타 수 감소 | 조준 실수의 대가가 커진다 |

**측정 지표** (16장 연계)

| 지표 | 목표 |
|---|---|
| 전투당 총 턴 수 중앙값 | 16 ~ 20 |
| 전투당 실시간 | 2 ~ 3분 |
| 런 완주 시간 | 55 ~ 70분 |

### 9.6 라이프 — 런을 관통하는 자원

**⬜ D-12와 함께 재검토 중**

라이프는 「전투 간에 소모되는 것이 아무것도 없다」는 전제 위에 설계되었다. 그 전제가 D-12의 초안(전원 부활 + 체력 리셋)이었고, 지금 D-12가 미정으로 돌아갔다.

| D-12를 어떻게 정하느냐 | 라이프의 역할 |
|---|---|
| 전원 부활 + 체력 리셋 (초안) | **라이프가 런의 유일한 소모 자원.** 지금 설계 그대로 |
| 체력 이월 | 체력이 이미 소모 자원이므로 **라이프와 역할이 겹친다.** 라이프를 줄이거나 없앨 수 있다 |
| 파괴된 기물 영구 손실 | 덱 자체가 소모된다. **라이프가 오히려 과잉**이 될 수 있다 |

**두 결정을 함께 정해야 한다.** 아래는 D-12가 확정되었다고 가정한 라이프 규격이다.

| 항목 | 값 |
|---|---|
| 시작 라이프 | **3** |
| 일반 전투 패배 | **−1** |
| **엘리트 전투 패배** | **−2** |
| 보스 전투 패배 | **−1** |
| 라이프 0 | **런 종료** |

**엘리트가 −2인 이유**

엘리트는 분기 선택으로 **회피할 수 있다**(9.1). 즉 엘리트 노드에 들어가는 것은 언제나 자발적 선택이다.

- 유물이라는 보상이 걸린 도박이 되고, 라이프가 그 판돈이 된다.
- 「라이프 2로 엘리트에 들어갈 것인가」가 매 막마다 반복되는 판단이 된다.
- 보스는 반드시 조우해야 하므로 선택이 아니다. 따라서 −1로 둔다.

**부수 효과**

| 항목 | 내용 |
|---|---|
| 실력 지표 | 「라이프를 얼마나 남기고 3막에 닿았는가」가 자연스러운 성취 척도가 된다 |
| 난이도 노브 | 승급 단계에서 시작 라이프를 줄이면 그대로 난이도가 된다 |
| 보상 설계 재료 | 라이프 +1 유물, 라이프를 거는 이벤트 등이 성립한다 |
| 60분 런 보호 | 조준 사고 한 번으로 한 시간이 날아가지 않는다 |

**패배 전용 보상**

> 패배해도 **패배 전용 보상**을 받는다. 완전 무보상이 만드는 죽음의 나선을 막기 위함이다.

설계 원칙 (⬜ 구체 내용 미정):

- 승리 보상은 **성장**(기물·유물), 패배 보상은 **정보와 완충**에 가깝게 두면 나선이 생기지 않는다.
- 이미 시스템에 걸려 있는 것 하나: 패배해도 그 적을 **조우**했으므로 도감이 열리고 발동한 능력이 공개된다(7.10.2.1). 「졌지만 배웠다」가 규칙으로 이미 존재한다.

**⬜ 미정**

| 항목 |
|---|
| **D-12(전투 종료 후 처리)와의 정합** — 위 표 참조 |
| 패배 전용 보상의 구체 내용 |
| 라이프 회복 — **휴식 노드에서 1 회복** (10.2) |
| 라이프 최대치 상향이 가능한지 |
| 패배한 노드에서 다음 노드로 어떻게 진행하는지 (경로 선택권이 남는지) |

### 9.7 개발상의 주의 — MVP 검증 사이클

1런이 60분이 되면서 **「1런 완주」를 MVP 판정으로 쓰면 검증 1회에 1시간**이 걸린다. P4~P6의 반복 속도가 크게 떨어진다.

**대응 방침**

- 막 수·층 수를 `acts.json` 데이터로 두고 **개발 빌드에서는 1막 5층 등으로 줄여 돌린다.** 구조 코드는 동일하므로 검증 사이클만 짧아진다.
- P4의 완료 판정을 **「1막 완주」**로 두고, 3막 전체 완주는 P6 밸런싱 단계에서 확인한다.
- 배치 시뮬 러너는 실시간과 무관하게 돌아가므로 밸런싱에는 영향이 없다.

### 10.2 기물 영입 — 태그 가중치 (확정)

> **모든 전투 보상에 기물 영입이 기본 포함된다.** 선택지 구성은 보유한 태그에 따라 편향된다.

| 항목 | 내용 |
|---|---|
| 영입 기회 | 전투마다 1회 (런 전체 18~21회) |
| 가중치 대상 | **시너지가 활성화된 태그만** |
| 가중치 크기 | 그 태그의 **미중복 기물 수**에 비례 |
| 미중복 | 같은 기물을 2개 들고 있어도 1로 센다 |
| 다중 태그 | 기물은 태그를 최대 2개 가지므로 여러 태그의 가중치가 겹칠 수 있다 |

**「활성화된 시너지만」이 만드는 구조**

시너지는 **배치** 기준으로 발동한다(7.1.1). 따라서 확률업도 **직전 전투의 편성**에 따라 결정된다.

| 국면 | 상태 |
|---|---|
| 런 초반 | 같은 태그가 2개 모이기 전까지 시너지가 없다 → **가중치 없음. 완전 무작위 영입** |
| 첫 시너지 발동 (계수 2) | 그 태그의 확률이 오르기 시작한다 → **눈덩이 시작** |
| 이후 | 계수가 오를수록 더 나온다. 빌드가 굳어진다 |

- 최소 발동 계수가 2이므로(7.1.1) **런 초반의 무작위 구간이 확보된다.** 같은 태그 둘을 모으는 순간이 그 런의 방향이 정해지는 지점이다.

- 초반에는 자유롭게 모으다가, **어느 순간 방향이 정해지고 그 뒤로는 가속**된다. 로그라이트의 전형적인 성장 곡선이 태그 하나로 만들어진다.
- 보유 10 / 출전 5이므로 **어떤 시너지를 켤 것인가 = 다음 영입 확률을 무엇에 걸 것인가**가 된다. 편성이 전투 판단이자 성장 판단이 된다.
- 시너지를 껐다 켜는 것으로 영입 방향을 바꿀 수 있으므로, 빌드를 갈아타는 경로도 열려 있다.

**이 규칙이 세 가지를 동시에 푼다**

| 문제 | 해결 |
|---|---|
| 합성 재료가 안 모인다 | 태그 확률이 오르면 풀이 좁아져 **같은 기물이 다시 나올 확률도 함께 오른다** |
| 태그 빌드가 성립하지 않는다 | 시너지를 켜면 가속된다. 빌드에 방향성이 생긴다 |
| 무지개·킹 해금이 비현실적이다 | `원소` 5종·`체스` 5종 동시 보유가 **가중치를 타고 달성 가능한 목표**가 된다 (7.10.1) |

> 첫 시너지를 무엇으로 켜느냐가 그 런의 방향을 정한다. 로그라이트에서 이는 단점이 아니라 **런마다 다른 이야기를 만드는 장치**다.

**무태그 기물의 소외 — 해소 예정**

태그가 없는 기물은 가중치를 받지도 주지도 못하므로 합성이 훨씬 어렵다.

> **처리: 무태그 기물에 태그를 부여한다 (확정).** 역할군은 전 기물 필수, 테마는 해당되는 경우만. 구체 배정은 7.1.3에 있으며 ⬜ 승인 대기.
> 바둑돌만은 **의도적으로 무태그**다. 어떤 시너지에도 기여하지 않는 순수 기준 기물로 남는다.

**⬜ 미정**

| 항목 |
|---|
| 가중치의 구체적 크기 (미중복 1종당 몇 %인지) |
| 시너지가 여러 개 켜져 있을 때의 합산 방식 |

| 이미 보유한 기물이 선택지에 나올 때의 표시 (합성 예고) |
| 영입을 스킵할 수 있는지, 스킵 시 대체 보상 |

### 10.3 휴식 노드 (확정)

셋 중 **하나**를 고른다.

| 선택지 | 내용 |
|---|---|
| **라이프 1 회복** | D-24의 라이프를 1 회복 |
| **기물 합성** | 같은 레벨의 같은 기물 2개를 합쳐 +1레벨 (7.9) |
| ⬜ 3번째 선택지 | 미정 |

**설계 의도**

- 두 선택지가 **완전히 다른 축**을 건드린다. 라이프는 「살아남기」, 합성은 「강해지기」다.
- 라이프가 1 남았을 때는 회복이 압도적으로 무겁고, 여유가 있을 때는 합성이 매력적이다. **상황이 선택을 만든다.**
- 합성 재료를 모아둔 상태에서 라이프가 깎이면, 두 개를 든 채로 하나를 포기해야 한다. 휴식 노드가 매번 고민할 가치가 있는 칸이 된다.

**⬜ 미정**

| 항목 |
|---|
| 3번째 선택지 (기물 방출 / 다음 전투 선제 효과 / 소모품 획득 등) |
| 한 노드에서 합성을 몇 번 할 수 있는지 |
| 라이프가 최대치일 때 회복 선택지의 처리 |

### 10.4 패배 전용 보상 — 보복형 (확정)

> **패배하면 다음 전투를 강화하는 일회성 효과를 받는다.**

| 항목 | 내용 |
|---|---|
| 성격 | **보복형.** 다음 전투 1회 한정 강화 |
| 목적 | 연패를 끊는다. 죽음의 나선 방지 |
| 덱 성장 | 없음. 기물·유물은 주지 않는다 |

**설계 원칙**

- 승리 보상은 **영구적 성장**, 패배 보상은 **일회성 완충**이다. 이 구분이 유지되는 한 나선이 생기지 않는다.
- 지고도 아무것도 못 얻는 구간이 없으므로 **라이프 3이 실질적으로 3번의 재도전**으로 기능한다.
- 이미 시스템에 걸려 있는 것: 패배해도 그 적을 조우했으므로 도감이 열리고 발동한 능력이 공개된다(7.10.2.1). 「졌지만 배웠다」가 별도 설계 없이 성립한다.

**⬜ 미정**

| 항목 |
|---|
| 강화의 구체 내용 (스탯 버프 / 선제 배치 / 적 약화 / 소모품 지급 중 무엇인지) |
| 강화 강도 |
| 여러 번 연패했을 때 중첩되는지 |
| 엘리트 패배(−2)는 더 강한 보복 보상을 주는지 |

## 12. 적 AI

### 12.1 알고리즘 (확정)

```
1. 후보 샷 생성 (각도 × 파워 격자)
2. 각 후보를 결정론 시뮬레이터의 사본에서 끝까지 실행
3. 평가 함수로 채점
4. 상위 후보 중 선택
5. 등급별 오차를 주입한 뒤 실제 발사
```

결정론 물리(D-10)이기 때문에 AI가 **실제 결과를 미리 정확히 알 수 있다.** 난이도는 계산 정확도가 아니라 **주입하는 오차의 크기**로만 조절한다 (D-17).

### 12.2 평가 함수 구성 요소

| 항목 | 부호 |
|---|---|
| 플레이어에게 입힌 피해 | + |
| 플레이어 기물 파괴 | + |
| 자신·아군의 피해 및 파괴 | − |
| 자신의 최종 위치 위험도 (소멸 영역 근접) | − |
| 중립 기물과의 충돌 위험 | − |

**AI가 고려해야 하는 시스템**

| 시스템 | AI 반영 |
|---|---|
| 시너지 (7.1.2) | 플레이어의 활성 시너지를 피해 예측에 반영. `제어`·`강철`이 켜져 있으면 피해 기댓값이 낮아진다 |
| `체스` 시너지 | **양 진영에 적용되므로**, 적 AI도 자기 체스 기물이 이득을 본다는 것을 계산해야 한다 |
| 토큰 (D-28) | 계수에는 포함되지 않지만 실체가 있는 기물이므로 물리 시뮬에는 그대로 참여한다 |
| 부착 (7.6.2) | 링크로 묶인 오브젝트는 충돌 응답이 없으므로 궤도 예측에 반영 |
| 좀비 감염 | 감염 진행도가 높은 아군을 때리는 것을 회피 대상으로 평가할지 ⬜ |

**확률 요소가 있는 경우 (D-18)**

AI가 사본 시뮬을 돌릴 때 RNG를 소비하면 실제 전투의 난수열이 어긋난다. 사본은 **별도 RNG 스트림**을 쓰고, 확률 효과는 **기댓값으로 평가**한다 (예: 50% 크리티컬 → 피해 기댓값에 반영).

**⬜ 미정**: 각 항목의 가중치, 후보 샷 격자 해상도, 등급 수와 등급별 오차 범위, AI 성향 도입 여부.

### 12.3 성능 제약

후보 샷 개수 × 시뮬 스텝 수 × 기물 수만큼의 연산이 매 턴 발생한다. GDScript로 감당되지 않으면 ① 2단계 탐색(거친 격자 → 정밀 격자) ② 조기 종료 ③ 시뮬 코어의 GDExtension 이관 순으로 대응한다.

**⬜ 미정**: 턴당 AI 사고 시간 예산.

## 14. 기술 아키텍처

### 14.1 결정론 원칙 (D-10)

> **Godot 내장 물리(RigidBody2D 등)는 사용하지 않는다.** 시뮬레이션 계층은 엔진과 완전히 분리된 순수 데이터 계층이며, Godot 노드는 그 상태를 그리기만 한다.

| 요구사항 | 구현 방침 |
|---|---|
| 부동소수점 비결정성 제거 | **`int64` 고정소수점**, 소수부 16비트 (`FIX_SCALE = 65,536`, Q47.16) (D-29) |
| 제곱근 | 정수 뉴턴-랩슨 자체 구현 |
| 삼각함수 | 한 바퀴 65,536 고정 각도. 사분면 4,096구간·4,097개 Q47.16 LUT + 선형 보간, 대칭 계산 (D-31) |
| 난수 | `xoshiro128**` 자체 PRNG (D-32). Godot `RandomNumberGenerator` 사용 금지. RNG 호출 순서와 서브스트림 키를 고정하고 소비 지점을 기물 ID·트리거 순으로 정렬한다 |
| 순회 순서 | 모든 반복은 기물 ID 오름차순 고정. Dictionary 순회 금지 |
| 안정 ID | `body_id`·`zone_id` 별도 uint32, 0 무효, 월드별 단조 증가·비재사용. 생성 요청 정렬 후 할당 (D-37) |
| 입력 | 마우스 좌표를 각도·파워 단위로 양자화한 뒤 시뮬에 전달 |
| 시간 | **120Hz**, 정확한 유리수 `1/120`. 정수 틱만 사용하고 `delta` 직접 사용 금지 (D-34) |
| 반올림 | 최근접, 절반은 0에서 먼 방향. 직접 시프트·정수 나눗셈에 의한 암묵적 절삭 금지 (D-33) |

**확정된 수치 영역 (D-29)**

- 표준 전장의 긴 변은 약 **1,000 논리 단위**로 잡는다.
- 위치의 지원 안전 범위는 **±8,192 논리 단위**다.
- 렌더 픽셀은 논리 단위와 분리하고 표시 단계에서만 변환한다.
- Q47.16의 이론상 표현 범위 전체를 물리 계산에 허용하지 않는다. 곱셈·내적의 `int64` 중간값 안전성을 기준으로 지원 범위를 별도 검증한다.

**물리 수치 안전 범위 (D-30)**

- 속도 벡터의 크기: **4,096 논리 단위/초 이하**
- P0·P1 초기 밸런스 발사 상한: **2,048 논리 단위/초 이하**
- 물리 무게: **1~256**
- 임펄스 절댓값: **2,097,152 이하**
- 범위 밖 설정·콘텐츠 데이터는 조용히 clamp하지 않고 로드 또는 테스트 단계에서 실패시킨다.

**고정 각도와 삼각함수 (D-31)**

- 각도는 `0~65,535` 범위의 정수로 저장하고 `& 0xFFFF`로 순환시킨다.
- `0`은 오른쪽 `+X`, 양의 방향은 화면 좌표 기준 시계 방향이다.
- 45°=`8,192`, 90°=`16,384`, 180°=`32,768`, 270°=`49,152`로 정확히 표현한다.
- 사분면 하나를 4,096구간으로 나눈 4,097개 Q47.16 사인 값을 저장한다.
- 나머지 사분면은 대칭으로 계산하고 LUT 구간 사이는 고정소수점 선형 보간한다.

**결정론 PRNG와 서브스트림 (D-32)**

- 알고리즘은 `xoshiro128**`, 상태는 32비트 워드 4개다.
- GDScript에서는 각 워드를 `int64`에 저장하되 모든 연산 뒤 `& 0xFFFFFFFF`로 마스킹한다. `int64` 오버플로에 의존하지 않는다.
- 런 시드는 64비트 값이며 저장·표시는 16자리 16진수로 통일한다.
- 서브스트림은 `루트 시드 + 용도 ID + 안정된 소유 ID + 순번`으로 파생하며 부모 스트림을 소비하지 않는다.
- 시드 혼합은 `fmix32`와 오버플로 없는 `mul_u32` 헬퍼를 사용한다.
- 범위 난수는 modulo 편향을 피하기 위해 rejection sampling을 사용한다.
- 확률은 부동소수점 없이 정수 `numerator / denominator`로 판정한다.
- 실제 전투 효과와 AI 평가 사본은 별도 용도 ID의 스트림을 쓴다.
- 스냅샷은 상태 4워드와 소비 횟수를 포함하며, 전부 0인 상태는 허용하지 않는다.

**고정소수점 반올림과 오류 처리 (D-33)**

- 기본 반올림은 가장 가까운 표현값을 선택하고, 정확히 절반이면 0에서 먼 방향으로 보낸다 (`+1.5→+2`, `-1.5→-2`).
- 고정소수점 곱셈·나눗셈·LUT 보간·입력 양자화에 같은 규칙을 적용한다.
- 제곱근은 음수를 받지 않으며 절반이면 위쪽 표현값을 선택한다.
- 덧셈·뺄셈은 정확 연산이고 반올림하지 않는다.
- `floor`, `ceil`, `trunc`는 명시적으로 필요한 알고리즘에서만 이름 있는 헬퍼로 호출한다.
- 시뮬레이션 코드가 직접 비트 시프트나 정수 나눗셈으로 암묵적 절삭을 만들지 않는다.
- 0 나눗셈과 승인 범위 밖 중간값은 실패 처리한다. 포화 연산과 조용한 clamp는 사용하지 않는다.

**고정 스텝 (D-34)**

- 시뮬레이션 주기는 **120Hz**다.
- `DT`는 Q47.16으로 근사하지 않고 `DT_NUM=1`, `DT_DEN=120` 유리수 연산으로 적용한다.
- `SimWorld.step()`은 정확히 한 틱을 전진하고 모든 시간·입력 시점을 정수 틱으로 기록한다.
- 프레임 지연이 생겨도 권위 시뮬레이션 틱을 버리지 않는다. 렌더 accumulator·보간·표시 생략은 시뮬레이션 밖의 책임이다.
- 빠른 이동의 추가 분할은 기본 틱을 바꾸지 않고 충돌 단계의 동적 서브스텝으로 처리한다.

**시뮬레이션 ID (D-37)**

- `body_id`와 `zone_id`는 별도 네임스페이스이며 의미상 `uint32`, GDScript 저장은 `int64`다.
- ID 0은 무효값이다. 각 `SimWorld`에서 1부터 단조 증가하고 파괴·제거된 ID를 월드 수명 동안 재사용하지 않는다.
- 초기 본체·존 요청은 안정된 `spawn_key`로 정렬한 뒤 ID를 할당한다.
- 런타임 생성 요청은 `(틱, 생성 원인 body_id, event_type_id, 이벤트 내 순번)` 순으로 정렬한 뒤 할당한다.
- 월드 복제와 스냅샷은 현재 ID와 다음 ID 카운터를 함께 보존한다.
- 외부 ID 지정은 스냅샷 복원과 테스트 픽스처에서만 허용한다.
- 콘텐츠 문자열 ID와 시뮬레이션 숫자 ID는 분리하며, uint32 범위 초과는 실패 처리한다.
- 새 전투의 새 `SimWorld`는 카운터를 다시 1부터 시작한다.

**SimEvent 레코드와 큐 (D-38)**

- 공통 순서 필드는 `tick:int64`, `substep:uint16`, `sequence:uint32`, `type_id:uint16`이다.
- 관계 필드는 `source_body_id:uint32`, `target_body_id:uint32`, `zone_id:uint32`, `cause_id:uint16`이며 대상 없음은 0이다.
- payload는 `position:FixVec2`, `vector:FixVec2`, `value_a:int64`, `value_b:int64`, `flags:uint32`의 고정 슬롯만 사용하고 미사용 필드는 0으로 채운다.
- Dictionary·Variant·문자열 payload를 사용하지 않는다. 큐에 추가한 이벤트는 수정하지 않는다.
- 큐 순서는 월드별 1부터 증가하는 `sequence`가 유일한 정본이다. 소비자는 cursor를 이동하며 틱 도중 큐를 재정렬·삭제하지 않는다.
- 스냅샷은 이벤트 큐, 소비 cursor, 다음 sequence를 함께 보존한다.
- type/cause enum 번호는 기존 값을 바꾸지 않고 새 값을 끝에만 추가한다. sequence 범위 초과는 실패 처리한다.
- P0-2 기본 타입은 `BODY_ADDED`, `BODY_REMOVED`, `BODY_STOPPED`다. 충돌·벽 반사·파괴 타입은 P0-3에서 추가한다.

**P0 상태 해시 (D-45)**

- 각 안정 틱 경계의 정규 `SimSnapshot` 바이트 전체를 표준 SHA-256으로 독립 해시한다.
- 내부 다이제스트는 32바이트, 로그·골든 픽스처 표기는 소문자 64자리 16진수다.
- `src/core/sim` 구현은 엔진 API에 의존하지 않는 순수 GDScript SHA-256을 사용한다. 테스트 어댑터에서만 Godot `HashingContext.HASH_SHA256`와 Python `hashlib.sha256`을 독립 참조값으로 사용한다.
- Godot 범용 `hash()`, Dictionary·String의 런타임 해시, 플랫폼별 기본 직렬화는 사용하지 않는다.
- 상태 해시는 회귀 검증용 지문이며 게임 판정, RNG 시드·서브시드, 콘텐츠 ID로 재사용하지 않는다.

확정된 안전 범위의 경계·오버플로 테스트 벡터는 P0-1에서 작성한다.

## 16. 검증 · 테스트 계획

| 테스트 | 방법 | 통과 기준 |
|---|---|---|
| 결정론 회귀 | 동일 시드·입력으로 다수 전투 실행 후 최종 상태 해시 비교 | 100% 일치 (플랫폼 교차 포함) |
| 관통 검사 | 최대 속도 발사를 대량 반복하며 겹침 깊이 기록 | 반지름 초과 겹침 0건 |
| 교착 검사 | 무작위 시드로 장시간 시뮬 | 최대 시간 초과율이 예산 이내, 강제 감속 후 100% 정지 |
| 기물 밸런스 | 헤드리스 AI vs AI 배치 대전 | 조합별 승률이 목표 밴드 내 |
| 전투 길이 | 배치 시뮬의 턴 수 분포 | 중앙값 15~20턴, 전투당 2~3분 (9.4) |
| AI 성능 | 최악 조건의 턴당 사고 시간 | 예산 이내 |
| **시너지 밸런스** | 태그별로 계수를 고정하고 배치 시뮬 | 특정 태그의 승률이 밴드를 벗어나지 않음 |
| **합성 도달률** | 런 시뮬에서 레벨 2·3 도달 빈도 측정 | 레벨 2는 흔하게, 레벨 3은 드물게 |
| **라이프 소모 곡선** | 런 시뮬에서 막별 라이프 잔량 분포 | 3막 도달 시 평균 1~2 잔량 |
| **해금 진행 속도** | 런 반복 시뮬에서 격파 해금 누적 | 초반 여러 런에 걸쳐 고르게 열림 |

**배치 시뮬 러너**는 P1 단계에 함께 만든다. `godot --headless` 로 수천 판을 돌려 CSV를 뽑는 도구다. **이 도구 없이 손으로 밸런싱하려는 시도는 실패한다.**

**⬜ 미정**: 각 통과 기준의 구체 수치.

## 17. 개발 로드맵 (MVP = 1런 완주)

| 단계 | 산출물 | 완료 판정 |
|---|---|---|
| **P0 · 시뮬 코어** | 고정소수점 수학, 원-원 충돌, 마찰, 벽 반사, 소멸 영역. 회색 박스 | 두 원을 튕겨 충돌시키고 벽에 반사시킬 수 있다. 결정론 회귀 테스트 통과 |
| **P1 · 전투 루프** | 드래그 조준 + 궤적선, CTB, 피해 공식, 트리거 버스, 승패. 배치 시뮬 러너 | 개별 기물 없이 스탯만으로 팀 전투를 끝까지 진행할 수 있다 |
| **P2 · 콘텐츠 기반** | 기물·적·맵·환경 요소 구현 | **데이터 JSON만 추가해 새 기물을 만들 수 있다 (코드 수정 0)** |
| **P3 · AI** | 샷 평가, 등급 오차 | AI가 예산 시간 내에 납득 가능한 샷을 낸다 |
| **P4 · 런 루프** | 노드맵, 보상, 유물·소모품, 덱 관리 | **1막을 완주할 수 있다.** 층 수를 데이터로 줄여 검증 사이클을 짧게 유지 (9.6) |
| **P5 · 폴리시** | 픽셀아트 교체, 이펙트, 사운드, 튜토리얼 | 외부인이 설명 없이 첫 전투를 이해한다 |
| **P6 · 밸런싱** | 배치 시뮬 기반 수치 조정, 해금 | **3막 전체 완주 가능.** 16장 테스트 전 항목 통과 (MVP 달성) |

선행 관계: P0 → P1 → (P2 ∥ P3) → P4 → P5 → P6

### 17.1 타협 불가 항목

1. **P0의 결정론** — 무너지면 P3(AI)과 P6(밸런싱)이 통째로 불가능해진다.
2. **P2의 데이터 주도 설계** — 능력을 코드에 하드코딩하면 콘텐츠 확장에서 붕괴한다.
3. **P1의 배치 시뮬 러너** — 밸런싱의 유일한 수단이다.

**⬜ 미정**: 각 단계의 기간, 전체 일정.
