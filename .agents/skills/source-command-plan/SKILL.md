# source-command-plan

구현 전에 목표를 저장소 계약에 맞는 실행 단계로 나눌 때 사용한다. 이 스킬 자체는 파일이나 외부 상태를 바꾸지 않는다.

## 절차

1. `AGENTS.md`, `docs/command-catalog.md`, `pipeline/commands/orchestration.md`를 읽는다.
2. `pipeline/scripts/status.py --json`으로 현재 프로젝트·태스크·환경 상태를 읽는다.
3. 사용자의 목표를 카탈로그에 있는 명령과 승인된 명세에 매핑한다.
4. 선행 조건, 의존성, 자동 검증, 사람 승인 지점을 순서대로 정리한다.
5. `⬜ 미정` 값이나 승인되지 않은 핵심 동작은 구현 단계가 아니라 승인 결정으로 분리한다.
6. 최소한의 안전한 다음 단계와 완료 기준을 제안하고 사용자 확인을 요청한다.

## 제한

- status 조회 외의 생성·변경 명령을 실행하지 않는다.
- 카탈로그에 없는 기능을 실행 단계로 꾸며내지 않는다.
- 사람 승인 단계를 자동 승인으로 처리하지 않는다.
- 비밀값은 존재 여부만 다룬다.
